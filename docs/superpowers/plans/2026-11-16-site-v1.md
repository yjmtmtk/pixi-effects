# The pixi-effects 1.0 site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** release pixi-effects 1.0.0, then put a new one-page site live. The site uses the PixiJS-pop look, its sample videos are made by fresh Opus agents on 1.0.0, and it has a small Lab page about the live video.

**Architecture:**

- **Three phases.**
  - Phase 1 runs on `main`: it removes the Playground and brings the AI-facing docs to their 1.0 state. Then 1.0.0 is released.
  - Phase 2 runs on the branch `site/v1`. It builds the new site with placeholder samples. Pages deploys every push to main, so this branch is not merged until the end.
  - Phase 3 makes the samples on the published 1.0.0, has the owner review them, and merges the site.
- **Built from data.** Sample metadata lives in one JSON file. `scripts/sync-site.mjs` writes it into the pages as generated regions, so the pages stay static HTML.
- **Live playback.** Every video plays live: a poster first, then the page itself in an iframe.

**Tech Stack:**

- static HTML/CSS/JS on GitHub Pages;
- the existing site tooling: `scripts/site-parts.mjs`, `sync-site.mjs`, `stage-site.mjs` and `site-links.mjs`;
- vitest, plus the real-Chrome harness in `tests/support/browser.ts`;
- the `claude -p` trial harness, for making the samples.

**Spec:** `docs/superpowers/specs/2026-11-16-site-v1-design.md` (read it first; this plan argues from it).

## Global Constraints

**Look**
- Direction A, "PixiJS sibling". Background is a gradient from `#fcfbfd` to `#efecf8`.
- Ink `#1d1630`, secondary text `#5b5272`.
- Accents: pink `#e91e63` (primary), violet `#8b5cf6`, sky `#38bdf8`, orange `#f2a65a`.
- Bold type with tight tracking, pink pill buttons, white cards with soft violet shadows.
- Light only (my call, allowed by the spec): the theme switch goes away.

**Words and pages**
- All site copy is in English. The only other languages are the hero's example sentences: **English, 日本語, 中文, Español, 한국어**.
- Landing sections, in this order:
  1. hero;
  2. "Make a promo video for this project.";
  3. one-sentence pieces (4–5);
  4. refined pieces (2–3);
  5. start in 30 seconds;
  6. for the curious (quiet);
  7. then the footer.

**Samples**
- Made by Claude Opus only, on the published 1.0.0.
- "1 message, unedited". At most "best of 3", and the page says so.
- The owner reviews every piece before it goes live.

**Playback and media**
- Everything plays live: a poster first, then the page itself.
- Only ONE MP4 is committed: the Lab comparison clip.
- Posters are small JPGs.

**What goes**
- The Playground is removed as a whole feature.
- Removed from the site: the old gallery, `examples/films`, `examples/showreel` and the `examples/interactive` index.

**Release rules**
- The owner gives an explicit go before any push, tag or release, and runs `npm publish` themselves.
- Use single git commands, not chained ones.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Quality**
- Phone width (390 px) must work.
- `prefers-reduced-motion` must be respected.
- No `href` / `src` may start with `/`, because the site is served under `/pixi-effects/`.

## Review Focus

1. **A 390 px phone with the 中文 or 한국어 tab selected.** Long text without spaces must wrap, and there must be no horizontal scroll. Pinned in Task 7.
2. **A browser where a live piece fails to start** (no WebGPU, and WebGL fails too). The poster must stay and a short note must appear, never an empty box. Pinned in Task 5.
3. **Starting a second piece while one plays.** Only one live iframe may run at a time; the first goes back to its poster. Pinned in Task 5.
4. **`prefers-reduced-motion: reduce`.** Nothing starts by itself; the hero waits for a click. Pinned in Task 5.
5. **The copy button for `npx skills add yjmtmtk/pixi-effects` where the clipboard is refused.** It must select the text, so it can be copied by hand. Pinned in Task 7.

### Task 5: The live player

**Files:**
- Create: `site/shared/live.js` (a plain script with no imports, loaded with `defer`) and its styles in `site.css`.
- Test: `tests/site/livePlayer.test.ts` (real Chrome, `tests/support/browser.ts`), with a fixture page `tests/site/fixtures/live.html`. The fixture has three players: two working test-film pages, and one page that throws in `movie.init`.

**Interfaces:**
- Produces this markup contract, used by Tasks 7–8:

```html
<figure class="live" data-page="<relative url of the piece page>" [data-autoplay]>
  <img src="<poster.jpg>" alt="<what the video shows>" width="…" height="…">
  <button class="live-play" aria-label="Play <title>">▶</button>
  <figcaption>…</figcaption>
</figure>
```

- Behaviour:
  - A click on the figure or the button replaces the poster with `<iframe src=data-page allow="autoplay; fullscreen">`, so the piece plays live.
  - `data-autoplay` starts it when it scrolls into view (IntersectionObserver, ≥ 50 % visible), unless `prefers-reduced-motion: reduce` is set.
  - At most one iframe is live on the page. Starting another puts the previous figure back to its poster.
  - If the piece page does not report `window.__ready` within 15 s, or its `window.__logs` holds `init failed`, the poster comes back with a note: "This browser could not play it live."
