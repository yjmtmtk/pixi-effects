# scene3d (PixiJS 3D as the main 3D engine) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `scene3d` layer type (entry `pixi-effects/3d`) that draws a `@pixi/3d` scene inside PixiJS's own renderer, as a function of the time, with every layer feature working on it.

**Architecture:** `Scene3DSequence extends Sequence` (mirrors `src/three/ThreeSequence.ts`): `build()` makes a `View3D` and runs the author's `setup`; `awaitFrameAt(t)` (duck-typed by `Movie._awaitVideoFrames`) runs `update(t)`; PixiJS draws the view with the stage. Opacity/blend go through an `AlphaFilter` the layer manages; `checkDeterminism` plugs into `canvasReport`.

**Tech Stack:** TypeScript, PixiJS 8.23, `@pixi/3d` 0.1.0, tsup, vitest + real-Chrome test films.

**Spec:** `docs/superpowers/specs/2026-11-13-scene3d-design.md` (read it first; this plan does not repeat its reasons).

## Review Focus

1. A scene3d layer inside a composition whose `alpha` keyframes fade it: the 3D must fade with its siblings (View3D ignores world alpha) — Task 4 test "fades with its parent".
2. A page that calls `movie.setVars` / `rebuild`: the old View3D is destroyed with no PixiJS warnings and the new one draws — Task 3 test "rebuild".
3. An author who loads a glTF with plain `new Model3D({ source })` (autoUpdate on by default): playback must still equal a seek — Task 3 test "a Model3D made without autoUpdate:false is still a function of the time".
4. An async `setup` that throws (bad URL): `movie.init` rejects with the layer's name in the message, not a hang — Task 3 test "setup throws".
5. Export (MP4) of a movie with a scene3d layer: the encoded frames show the 3D (not blank) — Task 3 test "export".
