# 0.17 AI の道具 — 設計メモ

状態: 承認済み・実装済み（6 つの決定は推しどおり。実装での調整は末尾）。実装計画: docs/superpowers/plans/2026-10-08-ai-tools-0.17.md。承認後に B へ追加: 存在しない ease への警告（スプリング実験で、GSAP が黙って別の動きにすることが分かった）。
読む人: オーナー。決めてほしいことは 6 章。
関連: fframes との比較（2026-10-08）、ロードマップ（0.17 → 0.18 Playground + WebMCP → 0.19 表現力）。

## 1. 目的

AI が動画を作って確かめる輪（作る → 見る → 直す）を、**速く・正確に**する。0.17 では次の 5 つを入れる。

| # | 中身 | 何が良くなるか |
|---|---|---|
| A | 部分書き出しと下書き書き出し（`range` / `scale` / `draft`） | 1 場面だけ・半分の大きさで、すぐ書き出せる。直す → 確かめるが速くなる |
| B | `check` の強化（見る場所を増やす、`--at`、`--draft`、フォント） | 場面の切れ目の不具合を見逃さない。特定の瞬間をすぐ見られる |
| C | 音の測定（LUFS、true peak、クリップ、無音、場面ごと、波形画像） | AI が音量を数字で判断できる |
| D | `onion`（残像を重ねた 1 枚の画像） | 動きの軌跡とイージングを 1 枚で確かめられる |
| E | Cookbook のレシピ 2 つ（データから量産、字幕） | 外側のスクリプトで済むことは、見本で足りる |

やらないこと: 新しい映像表現（0.19）、Playground と WebMCP（0.18）、GIF・連番画像・透過（0.21）、字幕や量産の組み込み機能（レシピで足りる）。

## 2. 現状（調べた事実）

- `movie.render(options)` は 0 フレームから最終フレームまで全部を書き出す。`RenderOptions` は `format`、`video`、`audio`、`motionBlur` だけ。範囲も縮小もない（`src/core/Renderer.ts`、`src/core/Movie.ts:62`）。書き出しの本体は `canvas を CanvasSource に流し、フレームごとに gotoFrame` する単純なループ。音声は `movie.audioBuffer` を丸ごと 1 本のトラックにする。
- `pixi-effects-render` は `--query`、`--motion-blur` などを持つが、範囲指定はない。
- `pixi-effects-check` は、ページを開き、警告・`movie.inspect`（全体を約 60 フレームおきに）・`inspectAudio`・コンタクトシート・本物の書き出し（全長、デコードして検査）をする。**書き出しが全長なので、重い作品では遅い**（例: 48 秒の映画は約 14 秒、モーションブラー 16 で 99 秒）。
- `movie.inspectAudio()` は、ピーク（dBFS）、1 窓ごとの RMS / ピーク / 明るさ（Hz）、音源ごとの情報、`issues`（リミッターがかかった、聞こえない層、終わりで切れた音）を返す。**LUFS も true peak も、無音区間も、場面ごとの集計も無い。**
- コンタクトシートは `movie.contactSheet({ count | frames })` で作れる。残像を重ねる機能は無い。
- フォントが無いことの検出は `src/text/measure.ts` に断片があるだけで、`check` には出ない。

## 3. 設計

### A. 部分書き出しと下書き書き出し

```js
await movie.render({ range: [2, 5] });          // 2〜5 秒だけ。秒で指定
await movie.render({ range: 'title' });         // 名前をつけた層の at 〜 at+duration
await movie.render({ scale: 0.5 });             // 出力の大きさを半分に
await movie.render({ draft: true });            // scale 0.5 + 品質 low + モーションブラーなし
```
CLI: `pixi-effects-render page.html --range 2:5` / `--scene title` / `--scale 0.5` / `--draft`。

- **範囲**：出力の時刻は 0 から始まる。音声は `audioBuffer` を同じ範囲で切り出し、先頭と末尾に短いフェードを付ける（プチ音を避ける）。範囲が動画の長さを超える、`from >= to`、存在しない名前は、**何ができなかったかを書いた例外**にする。
- **縮小**：まず「ステージのキャンバスを小さい 2D キャンバスに縮小コピーして、それをエンコードする」という安全な方法にする（レイアウトや 3D の状態を変えないため）。**速くなるのはエンコードとファイルサイズ**で、描画自体は変わらない。実測して、描画の解像度も下げる必要があるかを判断する（その場合は第 2 段階）。「約 1 秒」のような数字は、測ってから書く。
- **`draft`** は、`scale 0.5`、`video.bitrate: 'low'`、`motionBlur: false` の短縮形。意図は「確認用」で、そう名前を付けて文書にも書く。
- 決めること: 範囲は秒を正とし、フレームでは指定させない（AI にとって秒のほうが自然）。

### B. `check` の強化

1. **見る場所を増やす**：今の「全体を約 60 フレームおき」に加え、**全ての最上位の層（場面）の最初と最後のフレーム**と、**0.25 秒ごと**を `inspect` する（合計は 240 フレームまで。超えるなら 0.25 秒の間隔を広げる）。場面の切れ目で起きる文字切れを見逃さない。
2. **`--at`**：`--at 3.5,title@end,50%,f120` で、指定した瞬間の画像を `frames/` に実寸で書き、`at.png`（コンタクトシート）にもまとめる。書式: `3.5`（秒）、`50%`（全体の割合）、`f120`（フレーム）、`名前@start|mid|end`（名前をつけた層の始め・中ほど・終わり）。
3. **`--draft`**：`check` の書き出しを下書き（A）にする。**既定は今のまま全長の書き出し**（`check` は最後の確認だから）。AGENTS.md には「直している間は `--draft`、最後に 1 回だけ全長」と書く。
4. **フォント**：文字層の `fontFamily` のどれも使えない（ウェブフォントが未読み込み、または一覧のどれも見つからない）ときに、層の名前つきで警告に出す。判定は `document.fonts.check` と、描画幅の比較（フォールバックと同じ幅なら未解決の疑い）。誤検出が出やすいので、**確実なとき（ウェブフォントの読み込み失敗）だけ警告、疑いは review 欄**とする。
5. 終了コードは今のまま（0 = 問題なし、1 = 問題あり）。

### C. 音の測定

`movie.inspectAudio()` の戻りに次を足す（既存のフィールドは変えない）。

```js
loudness: { integratedLufs, truePeakDb, clippedSamples, silences: [{ from, to }] },
scenes:   [{ name, from, to, lufs, peakDb, silent }],     // 場面ごと
cues:     [{ t, name }],                                    // 音の始まり（sfx・音楽・音声ファイル）
```
- **LUFS**（ITU-R BS.1770: K 特性のフィルタ、400 ms のブロック、−70 LUFS の絶対ゲートと −10 LU の相対ゲート）。**true peak** は 4 倍オーバーサンプリングで求める。外部ライブラリは使わない。検証は、解析的に値が分かる信号（周波数と振幅が既知のサイン波）に対するテストで行う。
- **場面**：最上位の層で `name` があり、長さが 1 秒以上のもの。無ければ全体を 1 つの場面とする。
- **`issues` に足す**（AI が読むのは `issues`）：積算 LUFS が −24 より小さい（Web 動画としては小さすぎる。目安は −14〜−16）／−9 より大きい（大きすぎる）、true peak が −1 dBTP を超える、クリップがある、無音の区間がある（音声が付いている動画で 1 秒以上）。しきい値は定数 1 か所で、文書に書く。
- **波形画像** `check-out/<name>/waveform.png`：ページ内の 2D キャンバスで描く（依存なし）。場面の境目を縦線、音の始まりを目盛りで重ねる。
- 音楽機能（`music`）の既定の音量（ピーク −6 dBFS）が、この基準でどう見えるかを一度測り、警告が出すぎないか確かめる。

### D. `onion`

```js
const png = await movie.onionSkin({ from: 1, to: 3, count: 8, as: 'dataURL' });
```
- 範囲を等間隔の `count` 枚（既定 8）に分け、`snapshot` を 2D キャンバスで重ねる。後のフレームほど不透明にして（0.25 → 1）、動きの向きが分かるようにする。背景まで重なると見づらいので、**背景（最下層）はそのまま、動く部分が残像になる**ように、まず単純な重ね合わせで試し、見づらければ差分の重み付けにする。
- CLI: `pixi-effects-check page.html --onion 1:3` で `onion.png`。
- この版では**層を 1 つ指定する機能は入れない**（他の層を隠す処理が要るため。要望が出たら足す）。

### E. Cookbook のレシピ 2 つ

- **データから量産**：ページが `new URLSearchParams(location.search)` から名前や数字を読み、`for` ループで `pixi-effects-render --query "name=…&score=…"` を呼ぶ。シェルのスクリプトと、ページのコードの両方を載せる。
- **字幕**：SRT を読んで文字層の配列にする関数（約 30 行）。折り返しと下の余白、同じ時刻に重なる字幕の扱いまで書く。
- どちらも、既存の Recipes テストの仕組みで**動くことをテストに入れる**（SRT の関数は、サンプルを渡して層の `at` / `duration` を検査し、`movie.inspect` で文字切れが出ないことを見る）。量産は、ページを 2 つの `--query` で開いて文字が違うことを確かめる。

## 4. テスト

- 純関数（範囲の解決、`--at` の書式、LUFS / true peak、フォント判定の分岐）は、ブラウザなしの単体テスト。
- 実ブラウザ：`render({ range })` の出力の長さと音声の長さ、`scale` の出力サイズ、`draft`、`check --at` が書く画像、`check --draft`、`onion` の画像が空でないこと。
- 既存の全テストを通す。`check` の既存の出力（`report.json` の形）は変えず、足すだけにする。

## 5. リスク

- **範囲指定の音声**：切り出しの境目の誤差、AAC のプライミング（既存の補正との相互作用）。長さを 3 つ（動画・音声・指定範囲）で比べるテストで押さえる。
- **LUFS の正しさ**：実装の誤りは、見た目では分からない。解析的な値との照合を必ずテストにし、誤差の許容を書く。
- **`check` が遅くなる**：見る場所を増やす分の時間。240 フレームの上限と、実測した秒数を CHANGELOG に書く。
- **縮小**：描画は速くならない（第 1 段階）。期待を上げすぎない文書にする。
- フォントの誤検出（B-4）。review 欄に留める。

## 6. 決めてほしいこと（私の推し付き）

1. **「場面」の定義**を、最上位の層で `name` があるもの（推し）にするか。それとも、新しく `scenes` の配列を導入するか（データが増える、AI が書くものが増える）。
2. **`draft` の中身**を「大きさ半分・品質 low・モーションブラーなし」（推し）でよいか。
3. **`check` の既定の書き出し**は全長のまま、`--draft` で下書き（推し）。それとも既定を下書きにするか（速いが、最後の確認が弱くなる）。
4. **音量の警告のしきい値**（−24 LUFS より小さい／−9 より大きい／−1 dBTP 超）でよいか。
5. **版**は 0.17.0 でよいか。
6. 作業の順番は A → B → C → D → E（推し。A が B の `--draft` の土台）でよいか。

## 7. 実装での調整

- 音の助言（LUFS の範囲、−1 dBTP 超、無音）は `issues` ではなく新しい `notes` に出す（失敗にしない）。失敗にするのはクリップと 0 dBTP 超だけ。既存のギャラリー作品の `check` が助言で落ちないため。
- 無音の `notes` は 3 件まで（残りは件数）。効果音だけの作品で 9 行も出たため。データ（`loudness.silences`）は全件を持つ。
- 「場面」から、似た層を 1 行にまとめた行（`snow-far-# ×130`）を除いた。
- `pixi-effects-check` に `--query` を足した（量産レシピのページを、書き出しと同じ値で検査するため）。
- **測って分かったこと:** `draft` / `scale` は**ファイルを小さくするが、書き出しを速くしない**（48 秒 1080p の作品: 全体 20.8 s、`--draft` 20.6 s でファイルは 7 分の 1、`--range 10:15` 10.4 s）。時間を減らすのは範囲指定。文書はそう書いた。`check --draft` の説明も同じ。
- 存在しない ease への警告を B に加えた（スプリングの実験で、GSAP が黙って別の動きにすることが分かった）。
