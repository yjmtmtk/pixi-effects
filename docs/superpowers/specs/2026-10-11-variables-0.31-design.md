# 変数と作り直し（0.31）: 名前付き変数、`rebuild`、画面サイズへの追従

2026-10-11。ブランチ `feat/variables`。状態: 設計（承認待ち）。ロードマップの「Variables」の実装。
根拠: スパイクの実測（`docs/roadmap.md`、記憶 `project_roadmap-2026-10-11`）。

## 1. 何を作るか（一文）
**名前付きの変数を宣言し、値が変わったら構成を作り直して同じ時刻から続ける。** 音声は、変わっていなければミックスを使い回す。
これ一つで、画面サイズへの追従（リキッド）、言語やブランドの差し替え、縦横の切り替え、ホストのコードからの操作（スクロールやポインタ）が賄える。

## 2. 決めること（ここがレビューの中心）
| # | 決定 | 理由 |
|---|---|---|
| D1 | 作り直しは**全体**（L0）。層ごと・プロパティごとの部分再計算はやらない | スパイク: 実在の式は 0 個と 10 個、評価は約 40 µs。部分再計算は、複雑さに見合う得がない。L0 は 20 ms（音声なし） |
| D2 | 変数の値は**数値か文字列**。真偽値はなし | 式は数値、置換は文字列。必要なら `0` / `1` |
| D3 | 数値の式では、宣言した変数を**そのまま識別子**で読む（`x: 'W/2 + shift'`） | 既存の語彙（`W`, `GW`）と同じ。新しい記号を覚えさせない |
| D4 | 文字列では **`{name}`**（`text: '{title}'`, `fillColor: '{accent}'`, `asset: '{lang}-logo'`） | すでにある `{value}`（数え上げ）と同じ形。`$` は金額（`'$5'`）と衝突するので使わない |
| D5 | **予約語**は変数名にできない: `w h W H GW GH t d T contain cover value` と式の関数名（`sin cos … rand noise lerp clamp smoothstep mod step PI`） | 式の識別子と衝突するため。宣言時に警告し、その変数は無視する |
| D6 | 値は**構成を作るときに一度**だけ評価される（毎フレームではない）。`at` / `duration` は式を受けないので、変数は値の側にだけ効く（時間の構造は、JS で `composition` を作り直す `rebuild({ composition })` で変える） | 既存の仕様のまま。純粋タイムラインの前提を壊さない |
| D7 | 作り直しの**失敗**では、**古い構成がそのまま残る**。新しい構成を先に作り、成功してから入れ替える | 変数の値の誤り（式のエラー、足りないアセット）で映像が壊れないように |
| D8 | 連続入力（マウス、スクロール）は、ホストが `setVars` を呼ぶ。呼びが重なったら**最新の値だけ**で作り直す（合体） | 入力のソースは本体に入れない（ホストのコード、またはレシピ） |
| D9 | 0.31 では**やらない**: 層単位・プロパティ単位の再計算、オーディオ由来の変数、`at` / `duration` の変数化、変数の依存関係の一覧 | 必要が出てからでよい（ロードマップに残す） |

## 3. API

```ts
// 宣言
await movie.init({ ..., vars: { shift: 0, title: 'NORD', accent: '#e5399a' }, composition: {...} });

movie.vars                                   // 現在の値（読み取り専用）
await movie.setVars({ shift: 40 });          // 変えて、作り直す。変わらなければ何もしない
await movie.resize(1080, 1920);              // 画面の大きさを変えて、作り直す（W / H / GW / GH が追従する）
await movie.rebuild({ composition, vars, width, height });   // 一般形: 構成そのものも差し替えられる（JS でレイアウト関数を呼び直す用）
// どれも { ms, audio: 'reused' | 'mixed' | 'none', frame, playing } を返す
movie.on('rebuilt', e => …)                  // e = 上の報告 + { reason: 'vars' | 'resize' | 'rebuild' }
```

- 作り直しの間、再生中なら一度止めて、**同じフレーム**から続ける（失う時間は作り直しの分だけ）。ポスターが出ているときはポスターを保つ。`playUntil` の途中なら取り消す。
- `setVars` に宣言のない名前を渡したら、近い名前を言って無視する（did-you-mean）。
- `resize(w, h)` は、`init` の `width` / `height` と、構成のルートの `width` / `height` の**両方**を置き換える（ルートの大きさが 2 か所にある件: 食い違いの警告を同時に入れる）。
- `Controller` は `rebuilt` を聞いて、停止点の目印を引き直す。

## 4. 仕組み

### 4.1 作り直しの流れ（`Movie`）
`Movie.init` の「構成を作る」部分（`seededComposition` から最初のフレームの描画まで）を**切り出して**、`init` と `rebuild` の両方から使う。
1. `rebuild` は、指定を今の指定にかぶせて、新しい構成を**オフステージで**作る（`new CompositionSequence(...).build()`）。タイムラインも新しく作る。
2. 成功したら、古い構成を外して `destroy()`、新しい構成を `root` に付け、タイムラインを入れ替える。失敗したら新しい側だけを壊して古い側を残し、`error` イベントを出して reject する（D7）。
3. 同じフレームへ `_goto` し、再生中だったなら `play()` で続ける。
- 確認済み: 層の `destroy()` はアセットのテクスチャを壊さない（`Container.destroy()` の既定は子テクスチャを残す。画像は `Assets` の共有テクスチャを使う）。ただし、実ブラウザで、作り直しを重ねても描画が壊れないことを**テストで確かめる**（未確認）。
- 保持する物: `Application` と canvas、`Assets`（読み込み済み）、`AudioContext`。作り直すもの: 構成のツリー、タイムライン、（`resize` のとき）レンダラーの大きさと `cullArea`。

### 4.2 変数の評価
- **数値**: `Scope`（`src/expr/Scope.ts`）に、宣言した数値の変数を足す。`evaluateExpr` はすでに識別子を引くので、構文は変えない。
- **文字列**: 構成を作る前に、純粋関数 `applyVars(spec, vars)` で、`{name}`（宣言した名前だけ）を値に置き換えた**新しい仕様**を作る。入力の仕様は触らない。宣言のない `{x}`（`{value}` など）はそのまま残る。
- 変数の宣言は `movie.vars` に持ち、`init` の仕様（変数を置き換える前）を保持して、`rebuild` で再利用する。

### 4.3 音声のキャッシュ
- ミックスが重い（650〜770 ms）ので、**記述子の列が同じなら、前回のミックスを使い回す**。
- 鍵: 各記述子の（`buffer` の同一性 または `synth.key`）、`loop`、`start`、`end`、`initialVolume`、`volumeKeyframes`、全体の長さ、サンプルレート。`warp` / `sourceMap`（時間のリマップ: 関数）を持つ記述子が一つでもあれば、キャッシュせずに作り直す（正しさを優先）。
- 使い回せたとき、再生中の音は止めない（同じ `AudioBuffer` なので）。変わったときは、同じ時刻から鳴らし直す（途切れが出る）。
- `rebuild` の報告の `audio` に、`reused` / `mixed` / `none` を載せる（テストとツールが確かめる）。

## 5. ツールと検査（AI が目なしで確かめられること）
- `check` / `render` に **`--var name=value`**（繰り返せる）と **`--size WxH`**（`check` は `1920x1080,1080x1920` のように複数を許し、サイズごとに contact sheet を出す）。ページ側は何も書かなくてよい: ページが ready になったあと、ツールが `movie.rebuild({ vars, width, height })` を呼んでから、シート、検査、書き出しを行う。
- `check` の `vars` の行: 宣言した変数、使われていない変数（宣言したのにどこにも出てこない）、`{name}` が宣言にない場合（`{value}` と予約語を除く）、予約語の宣言を、警告として出す。
- 文書: `docs/dsl.md`（Variables）、`docs/api.md`、cheatsheet、レシピ `liquid-layout`（`ResizeObserver` + `resize`）と `variants`（言語と色）、pitfalls。

## 6. 4 つの関門（`docs/roadmap.md`）に照らして
1. 一般の場合は 1 行: `vars: { lang: 'ja' }`、`text: '{title}'`。新しい語は増やさない。
2. 既存の語彙: 式の識別子、`{value}` と同じ形。
3. 決定的: 書き出しは「台本 + 変数の値」で一つに決まる（`render --var`）。ランダムは従来どおりシード付き。
4. 間違いへの警告: 予約語、未使用、宣言のない名前（did-you-mean）。
5. 目なしで検査: `check --size` / `--var` と、`rebuilt` の報告（`audio: reused` など）。

## 7. テストの計画（先にテスト、各層で変異を確かめる）
- 純粋: `applyVars`（置換、宣言のない `{x}` は残る、入れ子の配列とオブジェクト、入力を壊さない）、予約語と名前の検査、`Scope` に変数が入ること、音声のキャッシュ鍵（同じ記述子 → 同じ鍵、`volume` が違う → 違う鍵、関数を持つ記述子 → キャッシュしない）。
- `Movie`（偽のレンダラー）: `rebuild` の流れ（同じフレームに戻る、再生中なら続く、失敗で古い構成が残る、呼びの合体、`playUntil` の取り消し、`rebuilt` の報告）。
- 実ブラウザ（WebGPU と WebGL）: 変数で画素が変わる、`resize` で `W` / `H` に追従する、作り直しを 20 回重ねても描画が同一、音声の `reused`、シークの順序で結果が変わらない。
- ツール: `check --size`、`--var`、`render --var`（小さなページで実際に走らせる）。

## 8. 実装の順序（各段階の終わりでテストが通る）
1. **純粋部分**: `applyVars`、予約語、`Scope` の拡張、音声キャッシュの鍵（`src/core/vars.ts`、`src/core/mixCache.ts`）。
2. **`Movie` の切り出しと `rebuild`**（vars なしの作り直し。まず `resize`）。実ブラウザで、アセットが壊れないことを確認。
3. **`vars`、`setVars`、`rebuilt`、音声キャッシュ**。`Controller` の追従。
4. **ツール**（`--var`、`--size`）と**警告**（未使用、未宣言、予約語）。
5. **文書、レシピ、API の一覧の更新**（`docs/api-surface.txt`）、CHANGELOG。
6. 全テスト、変更を知らないレビュー、リリース（0.31.0。あなたの許可を取ってから）。

## 9. リスクと、まだ分かっていないこと
- 作り直しの途中の画面（新旧の入れ替えの瞬間）: 同じフレームで描画してから入れ替えるので、一瞬の欠けはないはず。**実測で確かめる**。
- `resize` のとき、WebGPU のレンダラーの大きさ変更が安全か（スパイクは `destroy` + `init` で確認し、in-place の `renderer.resize` は未確認）。駄目なら、`resize` は canvas を作り直す（`Application` を作り直す）形にする。
- 文字の折り返しは、作り直しのたびに測り直すので、Web フォントの読み込み前後で結果が変わりうる（落とし穴 103 と同じ）。変数で言語を切り替えるとき、フォントが先に読まれている必要がある。
- 大きな映像（furano 級）で、作り直しの時間が、実用か（スパイクの実測: 音声なし 17〜25 ms、あり 645〜760 ms → キャッシュで音声分が消える見込み）。**実作品で測る**。
- 変数が多いと、`{name}` の誤字が増える。未宣言の警告で拾う。

## 10. 範囲外（0.31）
層単位・プロパティ単位の再計算、ポインタやスクロールなどの入力ソースの組み込み、オーディオ由来の変数、`at` / `duration` の変数化、変数の依存関係の一覧、変数のアニメーション（連続値の補間）。
