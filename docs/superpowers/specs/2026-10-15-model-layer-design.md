# The `model` layer: a glTF model as data (2026-10-15)

Status: design (revised after building: `model` is the spec language's own name under `docs/philosophy.md` "Engine names" — the type, the `model()` helper and the key table are in the core, the three.js drawing is `ThreeModelSequence`, and three-only options are in a `three: { renderer, antialias }` block). Approved by the owner in chat ("proceed") after the three/WebGPU work and the decision NOT to add Babylon.js (see `docs/superpowers/specs/` history and the memory note). v1 is built on three.js.

## Why

A `three` layer needs a `setup(ctx)` function: imperative code, which is what an AI writes least reliably and what the checker cannot see into. The owner's thesis is that a video is plain data. A glTF model that plays an animation, framed and lit with sensible defaults, should be one object:

```js
{ type: 'model', asset: 'models/fox.glb', animation: 'Run', initial: { x: 'GW/2', y: 'GH/2', anchorX: 0.5, anchorY: 0.5 },
  keyframes: [{ at: 0, to: { 'three.model.rotation.y': 6.28 }, duration: 6 }] }
```

## The spec (v1)

| Field | Meaning | Default |
|---|---|---|
| `asset` | URL of a `.glb` / `.gltf` (relative to the page). Loaded by three's `GLTFLoader` (`three/addons/loaders/GLTFLoader.js`: the page's import map needs `"three/addons/"`). Draco / KTX2 / Meshopt are not set up. | required |
| `animation` | A clip name, a clip index, or `false` (no animation: the model's bind pose). | the first clip, if there is one |
| `animationSpeed`, `animationOffset` | The clip time is `t × animationSpeed + animationOffset` (layer-local seconds). | 1, 0 |
| `loop` | `true`: the clip repeats; `false`: it holds its last pose. | `true` |
| `fit` | `'contain'`: the camera shows the whole bounding box of the model from a three-quarter view; `false`: no automatic camera (give `camera.position`). | `'contain'` |
| `camera` | `{ fov, position: [x,y,z], lookAt: [x,y,z] }`, each optional; overrides the automatic one. | fov 40, three-quarter view (from the side and above) |
| `light` | `'studio'`: a key, a fill and an ambient light; `'none'`: only the lights the file brings (`KHR_lights_punctual`). | `'studio'` |
| `width`, `height`, `resolution` | as on the `three` layer. | as there |
| `three` | `{ renderer: 'webgl' \| 'webgpu', antialias }`: what only three.js has, in a block named for it (the page default of `registerThree`). | `'webgl'`, `true` |

Keyframes use the same vocabulary as every layer, plus `three.<name>.<path>` for the objects the layer exposes: `model` (the glTF root), `camera`, `key`, `fill`, `ambient`.

## How (v1)

- `ThreeModelSequence extends ThreeSequence`. ThreeSequence gets three protected hooks (`userSetup`, `userUpdate`, `userDispose`) that call the spec's `setup` / `update` / `dispose`; ModelSequence overrides them. Everything else (the renderer, its WebGPU handling, the node frame, the layer's canvas becoming a Pixi texture, keyframe paths) is shared.
- **Time is ours.** The clip is posed with `AnimationMixer.setTime(clipTime)`, which resets and re-evaluates: a seek forward, backward or by jumps gives the same pose; the mixer is never attached to a ticker.
- **Auto-fit:** from the bounding box of the loaded scene: centre, direction (0.45, 0.3, 1) normalised (a three-quarter view); the distance is the smallest at which the 8 corners of the box, projected, fit the vertical and the horizontal field of view with a 10 % margin (a sphere would leave an elongated model small and seen head-on, found with Fox.glb); `near`/`far` from the distance. The bind pose is measured, so a clip that travels far needs an explicit camera.
- Dynamic `import()` of the loader: pages without a `model` layer never load the addon.
- `registerThree()` registers `three` and `model`. A `model()` helper types the spec like `three()`.

## Tests

- Unit (real three maths, mocked renderers; a fixture glTF generated by `scripts/make-model-fixture.mjs` into `tests/fixtures/spin-box.gltf`: a box that turns 360° in 2 s): the loader is called with the asset, the clip choice by name / index / `false`, the clip time formula (speed, offset, loop, hold), the mixer is never ticker-driven, auto-fit puts the whole box in the frustum, `camera` overrides, lights `studio` / `none`, the exposed objects for keyframe paths, a clear error for a missing clip name (listing the names) and for a failed load (naming the URL).
- Film `tests/films/model-layer`: the model is drawn (centre not background); the clip plays (t = 0.5 differs from 0); it loops (t = 2 equals t = 0); forward = backward; real time passing changes nothing; WebGL equals WebGPU within the measured bounds.

## v2 (not now)

The composition's own `camera` and `light` layers drive the model too (one `cameraPath()` flies through flat layers and the model). The units differ (pixels against glTF metres): it needs a rule for where the model sits in layer space.

## Not in scope

Draco / KTX2 / Meshopt decoders, several models in one layer (use several layers or a `three` layer), morph-target-only control, picking (`pick`), a Babylon backend.
