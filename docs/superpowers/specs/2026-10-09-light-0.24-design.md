状態: **承認待ち**（オーナーのレビュー前。承認されるまで計画も実装も書かない。0.23「合成」のメモ `2026-10-09-mattes-0.23-design.md` の承認が先）。

前提: 0.22.0 まで公開済み。試作（`docs/superpowers/spikes-0.23-0.25/light/`: `src-new/lighting.ts`・`LitMaterial.ts`・`LightSequence.ts`、`patch-modified.diff`、`probe.html`、`driver.mjs`、`steps.mjs`、デモの PNG 4 枚）は捨てる前提で、この版では**書き直す**。

## 1. 目的

「奥行き」の続き。0.21 で被写界深度が入り、2.5D の絵が映像らしくなった。次に足りないのは**光**。いまの `threeD` 層は、どの向きでも、どこにあっても、同じ明るさの平らなカードに見える。次ができない。

- **ライトを当てる**（点、スポット、平行光、環境光）。層の向き（`rotationX` / `rotationY`）と距離で明るさが変わる。
- **動くスポットライト**（タイトルを照らして横切る）。
- **影**（カードの影が、壁や床に落ちる）。
- **フォグ**（遠いほど霞む）。

書き方は、`camera` 層と同じ形の `light` 層（絵を持たず、`initial` とキーフレームで動かす）。

やらないこと: 鏡面ハイライト、光の当たる側と当たらない側の間の接触の影、影のついた色・透過、`threeD` でない層へのライト（これまでどおり、カメラの影響を受けない）、レイトレーシング、ノーマルマップ。

## 2. 確かめた事実

試作（Opus 級のエージェントが別の作業コピーで実施。私が報告と絵を読み、写した。**再現はしていない**）。測定は Apple M1 Pro のヘッドレス Chrome（WebGPU は Metal、WebGL は ANGLE 経由の Metal）。

- **絵**（`room-unlit-f60.png` と `room-lit-f60.png` 等を、私が見た）: 光なしは「平らな色のカード」、光ありは「空間」に見える。スポットの円、カードの影、床の明暗、フォグと被写界深度を重ねた絵（`room-shadow-shot-fog-dof-f60.png`）。**本物の改善で、見せ物ではない**。限界も出る: 平面だけ（鏡面なし、面どうしの接触の暗がりなし）、大きなやわらかいスポットの円は使いすぎると古く見える、層は距離順に描く（深度バッファなし）ので、「部屋」を作ると順序の限界が見える（床の原点を奥の縁に置く工夫が要った）。
- **方式**: フィルタでも追加の描画パスでもない。ライトを受ける層の `PerspectiveMesh` に、**Pixi のメッシュのシェーダーに 1 段足したカスタムシェーダー**を付ける。頂点シェーダーで格子点ごとに平面上の位置 `P = O + u·U + v·V` を求め、`(P/深度, 1/深度)` を出す。フラグメントシェーダーで割って、**遠近補正された正確な位置**を得る（最初の版は uv を Pixi のとおり補間し、傾いた面で最大 14.9/255 ずれた）。GL 側は、Pixi の high のシェーダーが WebGL1 として扱われる（`textureLod` なし、ユニフォーム配列を変数で引けない）ので、ES 3.00 を手書きする。WebGPU は Pixi のシェーダー部品を使う。
- **正しさ**: 独立した JS の基準（ピクセルごとの光線）と、点（逆二乗の減衰）・スポットの円錐・2 軸に傾いた面・平行光・急な面の羽根つきスポットで**最大 0.53/255**（WebGPU と WebGL で同じ）。光が面の裏にあるときは表は環境光だけ（誤差 0.2/255）。円錐の縁を硬く（羽根 0）すると 2.18/255（34,170 点中 3 点）。**白い環境光を強さ 1.0 にすると、光なしの絵と完全に一致**（差 0、両方）。
- **影**: 受ける側のシェーダーの中で、追加のテクスチャなしに計算する。落とす側の層は、すでにそのフレームで描かれた自分のテクスチャを、受ける側に渡す。画素ごと・ライトごとに、光への線と落とす側の平面の交点を求め、その uv のアルファを読む。縁のやわらかさは 16 サンプル（黄金角のらせん）で、半径は `shadowDiffusion` × （受ける面→落とす面）/（落とす面→光）で、**距離が離れるほど半影が広がる**。複数の落とす側は**最大値**で合わせる（掛け算だと、文字の影がカードの影の中にも出て間違い）。限界: 平面のみ、層は自分に影を落とさない、影の形は落とす側のアルファ（色つきの影なし）、受ける側 1 枚あたり落とす側は試作で 2（テクスチャの枠の数。4 までは現実的）、同じ合成の中のみ、見えない層は影を落とさない。
- **フォグ**: カメラの性質（`fogNear` / `fogFar` / `fogColor` / `fogAmount`）。どれかを書いたときだけ有効（被写界深度と同じ流儀）。画素ごとに、カメラの視線方向の深度から（床に本物の勾配が出る）。同じシェーダーの中で、ライトがなければコストはほぼ 0（20 層で +0.05 ms）。被写界深度との順序は、フォグが表面の一部で、ぼかしがその後。ライトとの順序は、陰影の後にフォグ。
- **コスト**（1080p、1 フレームの ms、WebGPU の基準 1.55 / 2.47 ms（5 / 20 層）、WebGL の基準 4.0–4.2 / 6.4–7.8 ms。WebGL の揺らぎは約 ±1.5–2 ms なので、影なし・硬い影の行は 0 と区別できない）:

  | 層 | ライト | 影 | WebGPU（基準との差） | WebGL（基準との差、2 回） |
  |---|---|---|---|---|
  | 5 | 1 | なし / 硬い / やわらかい | −0.1 / −0.1 / +0.6 | 揺らぎ / 揺らぎ / +0.4 |
  | 5 | 3 | なし / 硬い / やわらかい | −0.1 / +0.7 / +5.5 | −0.9…+1.6 / +0.4…+2.6 / +2.7…+4.0 |
  | 20 | 1 | なし / 硬い / やわらかい | +0.4 / +0.7 / +1.8 | +0.6 / +1.1 / +2.3…+5.6 |
  | 20 | 3 | なし / 硬い / やわらかい | +0.7 / +2.2 / +11.1 | −0.3…+4.4 / −0.5…+5.6 / +6.7…+11.2 |
  | 20 | フォグのみ | – | +0.05 | −1.5…+0.4 |

  → 光そのものはほぼ無料。**やわらかい影が高い**（ライト × 落とす側 × 画面の面積）。ライトもフォグもなければ、シェーダーは作られず、コストは 0。
- **決定性**: 前向き・後ろ向き・シャッフルのシークで差 0（動くライト、影を落とす 2 ライト、フォグ）。WebGPU と WebGL の差は、光なしの絵と同じ約 115 の縁の画素だけ（ライトは差を足さない）。MP4 の書き出しは両バックエンドで動く。
- **未検証**: 低スペックの GPU、Windows、Firefox、Safari。**ライトを受ける層のブレンド**、**入れ子・時間リマップした合成の中のライト**、`color` を GSAP の文字列で補間、フィルタを持つテキスト層を落とす側にすること、落とす側 3 つ以上、メモリ、長尺の書き出し。

## 3. 設計

### 3.1 書き方

`light` 層（`camera` と同じ形）と、層の 2 つの設定、カメラのフォグ。

```js
{ type: 'light', kind: 'ambient', initial: { intensity: 0.25 } },
{ type: 'light', kind: 'spot', initial: { x: 640, y: -100, z: 600, lookAtX: 200, lookAtY: 360, lookAtZ: 0, coneAngle: 35, coneFeather: 0.6 },
  keyframes: [{ at: 0, to: { lookAtX: 1080 }, duration: 4, ease: 'sine.inOut' }] },       // 動くスポット
{ type: 'shape', shape: 'rect', name: 'card', threeD: true, castsShadows: true, … },        // 影を落とす
{ type: 'camera', initial: { fogNear: 600, fogFar: 2400, fogColor: '#141824' } },          // フォグ
```

- **`light` 層**: `kind` は `'ambient' | 'point' | 'spot' | 'parallel'`。`initial` とキーフレームで動かせる項目: `x y z lookAtX lookAtY lookAtZ intensity color coneAngle coneFeather(0..1) radius falloffDistance shadowDarkness shadowDiffusion`。`falloff` は `'none' | 'smooth' | 'inverseSquare'`、`castsShadows`（このライトが影を作る）は固定の設定。
- **ライトの寿命**（0.24 の実装で決めた）: ライトは自分の `at` / `duration` の間だけ数える。**そのフレームで生きているライトが 1 つもない**（全部が寿命の外）ときは、`light` 層がない合成と同じに、光なしの絵で描く（AE も、ライトがなければ層は全明るさで描く）。環境光が寿命の外でも、点やスポットが生きていればそれだけで陰影がつく（暗い所は黒）。
- **ライトを受ける層**: **`light` 層が 1 つでもあれば、同じ合成のすべての `threeD` 層が受ける**（AE の「Accepts Lights」の既定と同じ）。受けたくない層は **`lit: false`**。**`light` 層が無い合成は、何も作られず、絵もコストも変わらない**。`threeD` でない層は、これまでどおり影響を受けない。
- **影を落とす層**: `castsShadows: true`。ライト側の `castsShadows: true` との組み合わせで影になる。
- **フォグ**: カメラの `fogNear` / `fogFar`（距離）、`fogColor`、`fogAmount`（0..1）。どれかを書いたときだけ有効。

### 3.2 仕組み

- `src/space/lighting.ts`（新規、Pixi なし）: ライトの状態と、陰影の計算（Lambert + 距離の減衰 + 円錐、受ける面の法線は、見えている側）の純粋関数。独立した JS の基準としてテストにも使う。
- `src/space/LightSequence.ts`（新規）: `camera` 層と同じ作りの、絵を持たない層（担体のオブジェクトを GSAP が動かし、`state()` を毎フレーム読む）。
- `src/space/LitMaterial.ts`（新規）: ライトを受ける層の `PerspectiveMesh` に付けるカスタムシェーダー（GLSL ES 3.00 を手書き + WGSL。Pixi のメッシュのシェーダーに 1 段足す）。ユニフォーム: 平面の `O` と軸 `U` `V`、カメラの位置と向き、環境光、フォグ、ライトごと（最大 8: 位置 + 種類、向き + 外側の円錐の余弦、色 × 強さ + 内側の円錐の余弦、減衰、影）、落とす側ごと（最大 2〜4: `O` `U` `V`）。
- `Layer3D` と `Composition.updateSpace`: ライトの状態を毎フレーム読み、受ける層のシェーダーに渡す（被写界深度と同じ流儀: **カメラ・ライト・層の純粋関数**。履歴を持たない）。**ライトもフォグも無いときは、シェーダーを作らない**。
- 被写界深度（0.21）のぼかしとは、フォグは表面の一部（ぼかしの前）、ブレンドはぼかしの後、の順を保つ。

### 3.3 警告（すべて「警告を出して、無視」。書き方の間違いは作るときに 1 回だけ言う）

`kind` の did-you-mean（`directional` / `sun` → `parallel`、`omni` / `lamp` → `point`）、`pointOfInterest` / `target` → `lookAtX/Y/Z`、`angle` → `coneAngle`、`castShadows` → `castsShadows`、ライトの項目を `initial` の外（層そのもの）に書いた、`coneFeather` が 1 を超える・`intensity` が 10 を超える（パーセントで書いた）、ライトがあるのに環境光がない（「ライトが当たらないところは真っ黒」）、`castsShadows` が層にだけある／ライトにだけある、落とす側が多い・ライトが 9 つ以上（どれが落とされるかを言う）、`castsShadows` を `threeD` でない層に書いた、`fogFar` が `fogNear` 以下、フォグの項目をカメラでない層に書いた、**ライトの層が `threeD`**（ライトは絵を持たない）。

### 3.4 `inspect`、タイムライン

- `inspect` の `threeD` 層の行に、**そのフレームの明るさ**（受けている光の合計の目安）を足す。AI が「照らされているか」を数字で確かめられる（被写界深度の `depthBlur` と同じ考え）。
- タイムライン図では、ライトの行を表示する（`camera` と同じ扱い）。

## 4. AI 親和性と、共通のパラメータルールとの整合

### 4.1 AI 親和性

| 観点 | 判定 |
|---|---|
| 共有の語彙 | `light` 層は `camera` 層と同じ形（`initial` / キーフレーム / 式 / `ease` / spring が、そのまま使える）。AE の言葉（ambient / point / spot / parallel、cone angle / feather、falloff）に揃える |
| よくある使い方は 1 行 | `{ type: 'light', kind: 'ambient', initial: { intensity: 0.25 } }` + 点かスポットを 1 つ |
| 間違いは作るときに直し方つきで警告 | 3.3 |
| 隠れた規則 | 3 つ: (a) ライトが 1 つあれば全部の `threeD` 層が受ける（`lit: false` で外す）、(b) ライトが当たらない所は黒（環境光を足す）、(c) 層は距離順に描かれる（深度バッファなし）。(a)(b) は警告、(c) は文書で見える |
| 使わない人へのコスト | 0（`light` 層もフォグもなければ、シェーダーは作られない。既存の作品は絵もコストも同じ） |

### 4.2 共通のパラメータルールとの整合

| 共通ルール | 新しい名前の扱い |
|---|---|
| 全層で同じ語彙 | `light` 層は `camera` 層と同じ作り。位置は `x y z`、見る点は `lookAtX/Y/Z`（カメラと同じ名前） |
| 固定の設定は最上位、動く値は `initial` とキーフレーム | `kind` / `falloff` / `castsShadows` / `lit` は固定の設定。位置・色・強さ・円錐・影の濃さと拡散は動く値 |
| 数は式でも書ける | `initial` の数は式が書ける |
| 色の書き方 | `color` は他の色と同じ書き方（`'#fff4e0'` など）。補間は、他の色のキーフレームの既定と同じ sRGB の混ぜ合わせ（`'#ff0000'` → `'#0000ff'` の真ん中は `#800080`。実機で確かめた。ライトに `colorSpace` は付けない） |
| 距離の単位は px、角度は度 | `x y z radius falloffDistance shadowDiffusion` は px、`coneAngle` は度 |
| 打ち間違い・別名は直し方つきの警告 | 3.3 |
| エンジン中立の名前（`docs/philosophy.md` の「Engine names」） | `light` / `kind: 'point'` などは仕様の言語の名前で、描画の実装（カスタムシェーダー）に依存しない。エンジンの名前を含む名前を作らない |

## 7. リスク

- **層は距離順に描く（深度バッファなし）**ので、「部屋」を作ると順序の限界が見える。文書に書き、レシピで「床の原点を奥の縁に置く」を示す。
- **やわらかい影が高い**（ライト × 落とす側 × 面積）。既定は硬い影。やわらかい影を多くのライトで使うと警告。
- **陰影は sRGB の値の上**（AE の既定と同じ）。強い光は白に張り付く。
- **Pixi のメッシュのパイプラインの変更**で、カスタムシェーダーが壊れうる（メッシュのアダプターが、シェーダーのユニフォームグループを割り当てるのに頼っている）。`pixi.js` 8.22 を基準にし、起動時の確認と警告を入れる。
- **ライトの数・落とす側の数の上限**（8 / 2〜4）。超えたらどれが落ちるかを警告で言う。
- 絵として、大きなやわらかいスポットの円は使いすぎると古く見える。ギャラリー作品とレシピで、控えめな使い方を示す。

## 8. 決めてほしいこと（私の推し付き）

1. **範囲**: 環境・点・スポット・平行の陰影と、カメラのフォグ、**影（硬いのを既定）まで入れる**（推し。合計 約 24〜34 h）。鏡面ハイライト、色つき・透過の影、落とす側 5 つ以上は入れない。
2. **既定の受け方**: `light` 層が 1 つでもあれば、すべての `threeD` 層が受ける。外すのは `lit: false`（推し。AE と同じ）。
3. **名前**: `kind: 'ambient' | 'point' | 'spot' | 'parallel'`、`castsShadows`、`lit`、カメラの `fogNear` / `fogFar` / `fogColor` / `fogAmount`（推し）。
4. **影は既定で硬く**、やわらかいのは `shadowDiffusion` で明示（推し。コストが読める）。
5. **ライトは最大 8、落とす側は受ける 1 枚あたり 2**（まず 2。計画の段階で 4 に上げる余地を測る）（推し）。
6. **陰影は sRGB の値の上**（推し。AE と同じ。リニア光は入れない）。
7. **ギャラリーに「光」の作品を 1 本付ける**（推し。スポットが横切る部屋と影）。

## 9. このあとのロードマップ（0.23 合成 → 0.24 光 → 0.25 描画の自由度 は承認済み）

- 0.25「描画の自由度」: シェーダー層と歪み（0.19 の試作に数字がある）。
- その後: 3D（`model` 層）、取り込み（Lottie・連番）、式（`t`）、LUT。
- 別件の既存不具合: 4000×2400 の `threeD` 層が WebGPU で黒く描かれる。
