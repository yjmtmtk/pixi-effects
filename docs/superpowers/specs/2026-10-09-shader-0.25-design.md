## 1. 目的

宣言的な DSL は、図形・文字・画像・動画・フィルタ・2.5D・光で、多くを描ける。描けないのは、**式で描く絵**（流れる雲、炎、波紋、プラズマ、ノイズの地形、数学的なパターン）と、**層の絵そのものを波打たせる歪み**。次の 2 つを足す。

- **シェーダー層**: `{ type: 'shader', fragment: '…' }` — Shadertoy の 1 パス（`mainImage`）を書くだけで、層になる。LLM が一番よく知っている書き方（GLSL）をそのまま受ける。
- **`warp` フィルタ**: 層の絵を波（`wave`）や陽炎（`haze`）で歪める。水面の下の文字、熱でゆらぐ空気。

やらないこと: 多段のシェーダー（バッファ・フィードバック）、背後の層を読むシェーダー（フィルターとしての使い方）、テクスチャ（`iChannel`）、マウス（`iMouse`）、WGSL を利用者に書かせること、層ごとの GL コンテキスト。

## 2. 確かめた事実

**試作**（私が自分で書いて、自分で測った。作業ツリー `HEAD` 上、`Shader.ts` 約 90 行。Apple M1 Pro のヘッドレス Chrome、WebGPU と WebGL の両方）。

- **方式**: ページ全体で **WebGL2 のコンテキストを 1 つ**共有し、層ごとにその共有キャンバスへ描いて、**層ごとの 2D キャンバスに `drawImage` で写す**。その 2D キャンバスが Pixi のテクスチャ（`Texture.from(canvas)` → `Sprite`）。`three` 層（`src/three/ThreeSequence.ts`）と同じ型（`awaitFrameAt(local)` が毎フレーム呼ばれ、`texture.source.update()`）。層ごとにコンテキストを持たないので、Chrome の約 16 個の制限に当たらない。
- **正しさ**: グラデーション（`uv` と `iTime` の関数）の画素が、手で計算した値と**同じ**（3 つの時刻で 3/255 以内、実際は一致）。前向き・ジャンプ・後ろ向きのシークで**差 0**。WebGPU と WebGL の両方で同じ。
- **透明**: 不透明が既定。`transparent: true` で `vec4(c.rgb * c.a, c.a)`（プリマルチプライ）にすると、緑の背景の上で青（アルファ 0.5）が `0,127,128`（期待どおり）。大きさの違う 2 層が 1 つのコンテキストを共有して、互いの絵を壊さない。
- **コンパイルエラー**: `#line 1` を使うと、エラーが**利用者のコードの行番号**で出る（`ERROR: 0:2: 'undefinedThing' : undeclared identifier`）。層は目立つ市松模様を描く（黙って空白にしない）。
- **コスト**（1 フレームの `snapshot` の中央値 = 描画 + 読み戻しなので、比べて読む）: 160×90 の重めのシェーダー（8 回の反復）20 層で、同じ数の矩形より **+11（WebGPU）〜+17（WebGL）ms**（1 層 約 0.5〜0.85 ms: キャンバスの寸法の設定、描画、コピー）。1920×1080 の全面 1 層で **+10 ms**（どちらも）。
- **未検証**: 低スペックの GPU、Windows、Firefox、Safari。シェーダーの無限ループ（GPU の暴走）は止められない。層の数が 100 を超える場合、`threeD`・マスク・マットと組み合わせたとき、書き出し（MP4）。

**既存の足場**: 時間を受け取るフィルタの仕組み（`TimeFilter`: `grain` が使う。`Movie` が毎フレーム `setTime(t)` を呼ぶ。決定的）、`GlProgram` / `GpuProgram` の 2 言語のフィルタの型（`Matte`・`LumaWipe`・`TransitionMask`）、名前つきフィルタの表（`pixi-filters` の `twist` `bulgePinch` `shockwave` `rgbSplit` がすでにある）。**無いもの**: 層の絵を波や陽炎で歪めるフィルタ、式で描く層。

## 3. 設計

### 3.1 書き方

```js
// シェーダー層: Shadertoy の mainImage。iResolution / iTime / iFrame は自動で宣言される。
{ type: 'shader', name: 'plasma', width: 1280, height: 720,
  fragment: `
    void mainImage(out vec4 fragColor, in vec2 fragCoord) {
      vec2 uv = fragCoord / iResolution.xy;
      float v = sin(uv.x * 10.0 + iTime) + sin(uv.y * 8.0 - iTime * 1.3);
      fragColor = vec4(mix(tint, vec3(0.1, 0.0, 0.3), 0.5 + 0.25 * v), 1.0);
    }`,
  uniforms: { tint: '#ff8040', speed: 1 },
  keyframes: [{ at: 0, to: { 'uniforms.speed': 3 }, duration: 4 }] },

// 歪み: 層の絵を波や陽炎でゆがめる
{ type: 'text', text: 'UNDER WATER', …, filters: [{ type: 'warp', kind: 'wave', strength: 8, scale: 60, speed: 1.5 }] },
{ type: 'image', asset: 'sky', filters: [{ type: 'warp', kind: 'haze', strength: 5, scale: 120, name: 'heat' }],
  keyframes: [{ at: 0, to: { 'filters.heat.strength': 14 }, duration: 3 }] },
```

**シェーダー層**
- **`fragment`**（文字列、必須）: `void mainImage(out vec4 fragColor, in vec2 fragCoord)` を書く（GLSL ES 3.00）。`fragCoord` は層の画素（原点は左下、Shadertoy と同じ）。**自動で宣言されるもの**: `iResolution`（`vec3`: 幅・高さ・1）、`iTime`（**その層のローカル時間**、秒。時間リマップした合成の中ではその合成の時計）、`iFrame`（`int`）。`#version` や `precision` や `main` は書かない。
- **`uniforms`**（任意）: 名前を `uniform` として宣言してくれる。**数 → `float`、2〜4 個の数の配列 → `vec2` / `vec3` / `vec4`、色の文字列（`'#ff8040'`）→ `vec3`（0..1）**。キーフレームでは `'uniforms.speed'`、ベクトルや色の成分は `'uniforms.tint.0'`（添字）で動かす（色の文字列は作るときに 3 つの数にして、動かすのは成分）。
- **`width` / `height`**（既定は合成の大きさ。式が書ける）、**`resolution`**（既定 1: 0.5 で半分の解像度で描いて拡大する。重いシェーダーの逃げ道）、**`transparent`**（既定 false: アルファを無視して不透明。true: `c.a` を使う）。
- **ふつうの層**: `initial`・`keyframes`・`mask`・`filters`・`blendMode`・`threeD`・`parent` など、すべてそのまま効く（ふつうのスプライトとして）。名前つきマットの源としても使える。
- **入れないもの**: `iMouse`・`iChannel0〜3`・`iDate`・`iTimeDelta`（書くと警告: 「この版にはない」）、多段、フィードバック、背後の層を読むこと。

**`warp` フィルタ**（`{ type: 'warp', kind, … }`）
- `kind: 'wave'`（既定）: 絵を、横波（`angle: 0` なら縦に揺れる波が横に進む）でずらす。`kind: 'haze'`: 滑らかなノイズの流れでずらす（陽炎、水面）。
- **`strength`**（ずらす最大のピクセル数、既定 6）、**`scale`**（波長・ノイズの大きさ、px、既定 80）、**`speed`**（1 秒に進む位相の周期数、既定 0.5。0 で止まる）、**`angle`**（度、既定 0）、**`seed`**（`haze` のパターン、既定 0）。`strength` などは `'filters.<name>.strength'` で動かせる。
- 時間は**そのフレームの時間**（`grain` と同じく、`Movie` が毎フレームそのフレームの時間を渡す。モーションブラーの中の小フレームも同じ時間。時間リマップした合成の中では、その合成のローカル時間）。**そのフレームだけから決まる**ので、シークの順序で差が出ない。

### 3.2 仕組み

- `src/sequences/Shader.ts`（新規）: 試作を書き直す。共有の GL コンテキスト（`src/core/glShared.ts`: 1 つ作って、ムービーが全部壊れたら閉じる）、プログラムのコンパイル（`#line 1`、エラーを利用者の行で警告）、層ごとの 2D キャンバス、`awaitFrameAt(local)`。**コンテキスト喪失**（`webglcontextlost`）は、次の描画で作り直す。WebGL2 が無ければ 1 度だけ警告して市松模様。
- `src/core/shaderChecks.ts`（新規、Pixi も DOM も使わない）: 静的な検査（`mainImage` がない、`gl_FragColor` / `texture2D` / `varying` / `#version`、`iMouse` など無いもの、`iTime` などを自分で宣言した、`while` と上限が定数でない `for`、`uniforms` の値の型）を、文を返す純粋関数にする。
- `src/filters/Warp.ts`（新規）: `GlProgram` + `GpuProgram` の 2 言語のフィルタ、`TimeFilter`。`wave` と `haze` は GLSL と WGSL で同じ式（整数ハッシュの値ノイズ。`sin()` に位相を直接渡さない: `grain` と同じ決定性の作法）。基準の JS（`warpOffset(kind, x, y, t, opts)`）を同じファイルに置き、テストの基準にする。
- `src/filters/named.ts`: `warp` を自前のフィルタとして登録（`grain` と同じ扱い）。`FILTER_TYPES` に足し、`suggestName` の別名（`distort`・`displace`・`ripple`・`wavy`・`heatHaze` → `warp`）。
- `layerKeys` に `shader` 型の許すキーと、`PROP_KEYS` に `uniforms` を足す。

### 3.3 警告（すべて「警告を出して、無視」。書き間違いは作るときに 1 回だけ言う）

`fragment` がない・文字列でない、`mainImage` がない（書き方を例で）、`gl_FragColor`（`fragColor` に書く）、`texture2D`（`texture`）、`varying` / `attribute`（要らない）、`#version`（書かない）、`main()` を書いた、自動の名前（`iTime` など）を宣言した、無いもの（`iMouse` `iChannel0` `iDate`）、`while` と上限が定数でない `for`（GPU が止まるおそれ）、コンパイルエラー（行番号つき。層は市松模様）、`uniforms` の値が数・数の配列（2〜4 個）・色の文字列のどれでもない、`uniforms` の名前が GLSL の識別子でない、`resolution` が 0 以下か 1 より大きい、`transparent` が真偽でない、WebGL2 が使えない、`warp` の `kind` が `wave` / `haze` でない（did-you-mean）、`warp` の `strength` が負か 200 を超える（px で書く）、`scale` が 0 以下。

### 3.4 `inspect`、タイムライン

- シェーダー層は `inspect` に普通の層として出る（大きさ・範囲・画面外）。`inspect` の項目の追加はない。
- タイムライン図では `shader` の行に色をつける。

## 4. AI 親和性と、共通のパラメータルールとの整合

### 4.1 AI 親和性

| 観点 | 判定 |
|---|---|
| 共有の語彙 | LLM が最もよく知るのは Shadertoy の `mainImage` と `iTime` `iResolution`。新しい名前を作らず、それをそのまま受ける。`warp` の `strength` `scale` `speed` `angle` `seed` は既存のフィルタ（`grain` `twist`）と同じ語彙 |
| よくある使い方は 1 行 | `{ type: 'shader', fragment: '…mainImage…' }`、`filters: [{ type: 'warp' }]` |
| 間違いは作るときに直し方つきで警告 | 3.3。コンパイルエラーは**自分のコードの行番号**で出る（これが AI の自己修正に一番効く） |
| 隠れた規則 | 3 つ: (a) `iTime` は層のローカル時間、(b) 不透明が既定（アルファは `transparent: true` のとき）、(c) 背後を読めない（フィルターではなく層）。(a)(b) は文書の 1 節、(c) は警告ではなく文書。**`texture2D` などの GLSL ES 1.00 の癖は警告で直す** |
| 使わない人へのコスト | 0（シェーダー層がなければ GL コンテキストは作られない。`warp` を使わなければフィルタも作られない） |

### 4.2 共通のパラメータルールとの整合

| 共通ルール | 新しい名前の扱い |
|---|---|
| 全層で同じ語彙 | シェーダー層は他の層と同じ（`initial` / `keyframes` / `mask` / `filters` / `blendMode` / `threeD`）。`width` `height` `resolution` は `three` 層と同じ名前と意味 |
| 固定の設定は最上位、動く値は `initial` とキーフレーム | `fragment` `transparent` `resolution` は固定の設定（最上位）。`uniforms` の値は動く値（`'uniforms.x'`） |
| 数は式でも書ける | `width` `height` と `uniforms` の数は式が書ける（`uniforms: { a: 'GW / 100' }`） |
| 色の書き方 | `uniforms` の色の文字列は他の色と同じ書き方。補間は成分の数値（sRGB）で、色の文字列を直接は動かさない |
| 距離の単位は px、角度は度 | `warp` の `strength` `scale` は px、`angle` は度 |
| 打ち間違い・別名は直し方つきの警告 | 3.3 |
| エンジンの名前を含む名前を作らない | `shader` / `warp` はエンジンの名前を含まない（GLSL / WebGL は言語・API の名前で、描画エンジンの名前ではない。`tests/docs/EngineNames.test.ts` を通す） |

## 5. テスト

- **単体（速い）**: `shaderChecks.ts` のすべての警告と、良い入力が空配列、`uniforms` の宣言の文字列を作る関数（型 → `float` / `vecN`）、ラッパーの行数（`#line 1` が利用者の最初の行）、`warpOffset` の手計算（`wave` の位相・`haze` の整数ハッシュ・`strength 0` が 0）、`warp` の名前の別名、層の許すキー。
- **ブラウザ（実機、WebGPU と WebGL）**: 試作と同じ（グラデーションの画素が `uv` と `iTime` の関数、シークの順序で差 0、コンパイルエラーの行番号と市松模様、大きさの違う 2 層、`transparent`）、**マスク・マット・フィルタ・`threeD`・ブレンドとの併用**、`uniforms` のキーフレーム（数・ベクトルの成分・色）、時間リマップした合成の中の `iTime`、`resolution: 0.5`、MP4 の書き出し。`warp` は基準（`warpOffset`）で画素の移動量を確かめる（縞の入った画像を歪めて、期待の位置に縞が来る）、`strength: 0` は歪めない画素一致、シークの順序で差 0、モーションブラーの中で同じ。
- **既存への影響**: シェーダー層と `warp` を使わない作品は**ピクセル一致**（前後を比べる）、新しい警告ゼロ（`noFalseWarnings`）。
- `scripts/test-changed.mjs` の領域に、新しいファイルを足す。

## 7. リスク

- **GPU の暴走（無限ループ）は止められない**。静的な警告（`while`、定数でない `for`）と文書の注意まで。
- **GPU が違うと画素は一致しない**（同じ機械では決定的）。文書に書く。
- **コスト**: 小さい層が多いと 1 層 約 0.5〜0.85 ms（コンテキストの切り替え）。100 層は重い。`resolution` と、層を大きく少なくする（1 枚の全面シェーダー）を文書に書く。
- **共有コンテキストの喪失**（タブの GPU リセット）。次の描画で作り直す。喪失の最中のフレームは市松模様。
- **WebGL2 が無い環境**: 警告と市松模様。
- 試作は 2D キャンバスへの `drawImage` で写したので、キャンバスの色空間（`srgb`）に GPU の色の違いが出うる。両バックエンドで実機を確かめた範囲では差 0。

## 8. 決めてほしいこと（私の推し付き — 推しで確定として進める）

1. **言語**: GLSL ES 3.00 の Shadertoy `mainImage` だけ（推し）。WGSL は書かせない。
2. **方式**: 共有 GL コンテキスト 1 つ + 層ごとの 2D キャンバスへコピー（推し）。層ごとのコンテキストにしない。
3. **組み込み**: `iResolution` `iTime` `iFrame` のみ（推し）。`iChannel`（画像アセットの入力）は次の版で検討。
4. **`warp`**: `wave` と `haze` の 2 種（推し）。地図（別の層）による変位は入れない。
5. **`uniforms`**: 数・2〜4 個の配列・色の文字列、キーフレームは成分で（推し）。
6. **不透明が既定**、`transparent: true` でアルファ（推し）。
7. **ギャラリーに作品を 1 本付ける**（推し: 流れるシェーダーの背景の上に、`warp` で水面の下に見える文字）。
