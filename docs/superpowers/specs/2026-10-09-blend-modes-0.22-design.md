# 0.22 ブレンドモード（CSS の 18 種）— 設計メモ

状態: **承認待ち**（オーナーのレビュー前。承認されるまで計画も実装も書かない）。
読む人: オーナー。決めてほしいことは 8 章（私の推し付き）。共通のパラメータルールとの突き合わせは 4.2。
前提: 0.21.0 まで公開済み。試作 C（`docs/superpowers/spikes-0.21-0.22/blend-modes/`: `blendModes.ts`、`spike.patch`、`pages/`）は捨てる前提の試作で、この版では**書き直す**。`cubic-bezier` イージングは 0.20.0 に入っているので、この版の中身は**ブレンドモードだけ**。
ロードマップの名前は「光と色」から**「ブレンドモード」**に直す（色の調整は `filters` の `colorMatrix` / `adjustment` / `hslAdjustment` / `colorGradient` で既にできる。LUT だけ未対応で、この版には入れない）。

## 1. 目的

今の `blendMode` は `'normal' | 'add' | 'screen' | 'multiply'` の 4 種。映像の「光と色の質感」には足りない。次ができない。

- **overlay / soft-light / hard-light**（写真・グラデーションを重ねて質感を乗せる）、**color-dodge / color-burn**（強い光とつぶれ）、**darken / lighten / difference / exclusion**、**hue / saturation / color / luminosity**（色だけ、明るさだけを重ねる）、**linear-burn**。
- 画像や映像に、グラデーションのライトリーク（光漏れ）を乗せる、ビネットを `multiply` / `soft-light` で乗せる、といった「普通の映像編集」の定番。

書き方は **CSS の `mix-blend-mode` と同じ名前**だけ（`blendMode: 'soft-light'`）。新しい項目は増えない。

やらないこと: LUT、層ごとの不透明度とブレンドの分離（`alpha` は今までどおり層全体にかかる）、ブレンドの分離グループ（`isolation`）、`plus-lighter`、色空間を変えたブレンド（CSS と同じ sRGB 値の上で混ぜる）。

## 2. 確かめた事実

試作 C が測った数字（私は再現していない。計画の最初の手順で、**本番の実装で測り直す**）。

- **Pixi 標準の高度なブレンドは使わない。** 登録の副作用（`import 'pixi.js/advanced-blend-modes'`）が要り、登録しないと**警告なしで通常描画**になる。WebGL は `useBackBuffer: true` が要るが Movie は設定していない。テンプレートの esm.sh の読み込みでは登録が別のバンドルに入って効かない。実装にもバグがある（soft-light は WebGPU でだけ反転、linear-light と saturation は誤り、アルファ 1 未満で色がずれる）。
- **自前の `BlendModeFilter` 18 種**: WebGL と WebGPU を Metal と SwiftShader の 4 構成で試し、すべて W3C の式と **1/255 以内**で一致した（アルファ 0.5 も含む）。サイズは非圧縮 4.7 KB（gzip 1.4 KB）。使うときだけ遅延読み込みにできる。使わなければ何も変わらない。
- **決定性**: 前向き・ジャンプ・後ろ向きのシーク、書き出し用のキャプチャ、スナップショットでバイト一致（同じ環境内）。GPU が違うと 2/255 程度ずれる。
- **コスト（1080p、層は全部で 20 枚、1 フレーム ms）**。高度なモードの層 0 / 5 / 20 枚で: WebGL（Metal）1.3 / 12.5 / 23〜37、WebGPU（Metal）1.4 / 1.8 / 3.6。**WebGL では高度なモードの層 1 枚あたり約 1.5〜2 ms**。10 秒・30 fps の書き出しで 20 層なら約 +12 秒。
- **今の実装（フィルタ付きの層は最後のフィルタにモードを付ける）は高度なモードでは壊れる。** フィルタ列の**最後にブレンドフィルタを足す**方式なら動く。
- **`maskInverted` は全ブレンドモードと壊れる。** `multiply` でも壊れる**既存の不具合**。
- **普通の入れ子の合成層はグループとして混ざらない**（子が別々に混ざる。今の add / screen / multiply も同じ）。`threeD: true` かフィルタを付けるとグループとして混ざる。
- 未検証: Safari、Firefox、Windows、Linux、モバイル、WebGL1 だけの環境、Pixi 8.21 以前、動画・画像層とのブレンド、プレゼンテーション用のプレーヤー、実際の書き出し経路での長尺、**0.21 の被写界深度フィルタとの併用**（3.2）。

## 3. 設計

### 3.1 書き方

`blendMode` の値に、CSS の名前を足す。**18 種**: 既存の `normal` `add` `screen` `multiply` に、新しく `overlay` `soft-light` `hard-light` `color-dodge` `color-burn` `darken` `lighten` `difference` `exclusion` `hue` `saturation` `color` `luminosity` `linear-burn`。

```json
{ "type": "image", "asset": "photo", "initial": { "x": "GW/2", "y": "GH/2" } },
{ "type": "shape", "shape": "rect", "width": "GW", "height": "GH", "anchorX": 0, "anchorY": 0, "blendMode": "soft-light",
  "fillGradient": { "stops": [[0, "#ff9a3c"], [1, "#3c5bff"]] } }
```
写真の上に、上が橙・下が青のグラデーションを `soft-light` で乗せる（夕景の色かぶり）。

```json
{ "type": "shape", "shape": "circle", "radius": 380, "blendMode": "color-dodge",
  "initial": { "x": 900, "y": 200, "fillColor": "#ff6a00", "alpha": 0.8 } }
```
強い光源（光漏れ）。

規則（少なく、1 行で言える）:

1. **`blendMode` は層の上下順で決まる**: その層より**下に描かれているもの全体（背景）**と混ぜる。上の層は混ぜる前の絵に影響しない。
2. **名前は CSS と同じ**（ハイフンつき）。`softLight` / `soft_light` のような書き方は、警告して `soft-light` を案内する。
3. **混ぜる計算は sRGB の値の上**（CSS と同じ。リニア光ではない）。
4. **`alpha` は混ぜたあとの層全体にかかる**（CSS の `opacity` と同じ）。
5. **`composition` に付けると子に引き継がれる**（今までどおり）。ただし、**子が別々に混ざる**。**まとめて 1 枚として混ぜたいときは `threeD: true` かフィルタを付ける**（文書に 1 節。`threeD` を付けても z 0・既定のカメラなら絵は変わらない）。
6. **高度なモードは重い**（WebGL で 1 層 1.5〜2 ms）。10 枚以上が同時に出ると警告する。

### 3.2 仕組み

- `src/core/blend.ts` が**検査表**（18 種の名前、基本 4 種と高度 14 種の区別、`suggestName` の候補）を 1 か所で持つ。`types.ts` の `blendMode` はその名前の型。
- **高度なモード**は `src/filters/blendModes.ts`（新規、遅延読み込み）に自前の `BlendModeFilter` 14 種。**Movie の init で、組成に高度なモードを使う層があるときだけ**（`usesAdvancedBlend(spec)`）動的 import して登録し、WebGL では `backBuffer.useBackBuffer = true` にする。使わない作品は今までとバイト一致・コスト 0（試作の「`useBackBuffer: false` を常に設定」は本番では**しない**: 今の挙動を変えない）。登録は**その Movie が使っている pixi のインスタンス**の `extensions` に対して行う（esm.sh のバンドルが別コピーでも効く）。
- **フィルタ付きの層**: フィルタ列の最後に、高度なモードのブレンドフィルタを足す。基本 4 種は今のまま（最後のフィルタの `blendMode`）。
- **`threeD` 層**: 射影メッシュ（`display`）に付ける。**被写界深度のぼかしが付くとき**（`Layer3D.setBlur`）は、今は `blendMode` をぼかしフィルタに移している。高度なモードのときは、ぼかしフィルタ → ブレンドフィルタの順に並べる（ぼかしてから混ぜる）。この併用は試作で未検証なので、計画の最初の手順で確かめる。
- **`maskInverted` と併用**: 手順 2 で原因を調べる。**直せるならこの版で直す。直せなければ、作るときに警告して通常描画にする**（黙って壊れたままにしない）。

### 3.3 警告（すべて「警告を出して、無視」。書き方の間違いは作るときに 1 回だけ言う）

`src/core/blend.ts` の検査表と `layerKeys` に載せる。直し方つき。

| 間違い | 警告の内容 |
|---|---|
| 知らない名前（`softlight`、`soft_light`、`overlay2`） | 「blendMode "softlight" is not supported; did you mean "soft-light"? (normal, add, screen, multiply, overlay, …)」 |
| `maskInverted` と併用（直せなかった場合） | 「blendMode と maskInverted は一緒に使えません。blendMode は無視されます。マスクを反転せず、マスクの絵のほうを反転してください」 |
| 高度なモードの層が 10 枚以上同時に出る | 「N 枚の層が高度な blendMode で描かれています。WebGL では 1 枚あたり約 2 ms かかります。重ねる層をまとめるか、add / screen / multiply にしてください」（1 回だけ） |
| 普通の合成層（フィルタも `threeD` もなし）に高度なモード | 警告しない（今の add / screen / multiply と同じ「子が別々に混ざる」。文書で 1 節） |

警告の総数は、ギャラリー全作品・ガイドの例・レシピで**ゼロ**のままであること。

## 4. AI 親和性と、共通のパラメータルールとの整合

### 4.1 AI 親和性

| 観点 | 判定 |
|---|---|
| 共有の語彙 | 新しい項目はない。`blendMode` の値が CSS の名前に増えるだけ。AI が CSS で知っている名前がそのまま使える |
| よくある使い方は 1 行 | `blendMode: 'soft-light'` |
| 間違いは作るときに直し方つきで警告 | 3.3。名前の打ち間違い・別名は `suggestName` |
| 隠れた規則 | 2 つ: (a) 普通の合成層に付けると子が別々に混ざる、(b) 高度なモードは重い。どちらも文書の 1 節と警告（b）で見える |
| 使わない人へのコスト | 0（高度なモードを使わなければ、遅延読み込みもバックバッファも動かない） |

### 4.2 共通のパラメータルールとの整合

| 共通ルール | 新しい名前の扱い |
|---|---|
| 全層で同じ語彙。新しい小さな言語を作らない | `blendMode` は既存の項目。値の名前は CSS の `mix-blend-mode` に揃える（既存の `add` は CSS にない名前だが、そのまま残す） |
| 固定の設定は最上位、動く値は `initial` とキーフレーム | `blendMode` は最上位の固定設定（今までどおり。動かせない） |
| 名前の意味は 1 か所で決まる | `particles` の `blendMode` オプションも同じ名前の表を使う（検査表が 1 か所） |
| 打ち間違い・別名は直し方つきの警告 | 3.3。`COMMON_ALIASES` に `softlight` などを足さず、`suggestName` が `soft-light` を案内する（ハイフンを外した形・アンダースコアの形に強い） |
| エンジン中立の名前 | CSS の名前なので、特定のエンジンの名前を含まない。将来、別の 3D エンジンが主になっても名前は変わらない |

## 5. テスト

- **単体（速い）**: 検査表の網羅（18 種、型との整合）、`suggestName` の案内、`usesAdvancedBlend`（入れ子の `sequences`・`mask`・パーティクルの `template` まで見る）、警告 3 種、**W3C の式を JS で書いた基準実装**（試作の式とは別に、仕様書から書く）と、シェーダー文字列の式の突き合わせ（式の表が基準実装と同じ入力で同じ値を返すことを、GPU なしで確かめられる範囲で）。
- **ブラウザ（実機）**: 14 種の高度なモードそれぞれで、既知の 2 色（背景と前景。アルファ 1 と 0.5）を混ぜた画素が、基準実装の値と **1/255 以内**（WebGPU と、`?backend=webgl` で WebGL の両方）。前向き・ジャンプ・後ろ向きのシークでピクセル一致。フィルタ付きの層、`threeD` 層、被写界深度と併用した層、`threeD` の入れ子の合成層で混ざること。使わない作品でフィルタ・バックバッファが作られないこと（`useBackBuffer` が変わらない）。
- **既存への影響**: `blendMode` を使わない既存の作品、または基本 4 種だけの作品は**ピクセル一致**。
- `scripts/test-changed.mjs` の領域に、新しいファイルを足す。

4. **`applyBlendMode` の配線**（フィルタ付きの層、`threeD` 層、被写界深度との順序）と、**10 枚以上の警告**。

## 7. リスク

- **自前シェーダーの保守**。14 種の式の表と、W3C 基準実装が突き合わせの唯一の守り。仕様書にある式だけを使い、勝手な近似を入れない。
- **WebGL のバックバッファ**（`useBackBuffer`）は画面サイズぶんのメモリと 1 層ごとのコピーを要する。使うときだけ有効にする（上のコスト表のとおり、20 層で 23〜37 ms）。書き出しが遅くなる作品が出る。警告と文書で知らせる。
- **GPU が違うと 2/255 程度ずれる**（試作の測定）。決定性は「同じ環境内でバイト一致」まで。文書に書く。
- **Pixi の内部への依存**: `BlendModeFilter` と `extensions` は Pixi の公開 API だが、8.21 以前と将来の版で挙動が変わりうる。`peerDependency` の範囲と、起動時の「登録できたか」の確認（できなければ警告して通常描画）を手順 3 に入れる。
- **`maskInverted` の既存不具合**が根深いと、この版に入らない。そのときは警告にして、別件にする。
- 被写界深度との併用、動画・画像層との混ざり方、Safari / Firefox は未検証。手順 1 で確かめる。

## 8. 決めてほしいこと（私の推し付き）

1. **この版の名前を「ブレンドモード」にする**（「光と色」から）。色の調整は既にあり、LUT は入れない。
2. **自前の 14 種を入れ、Pixi 標準の高度なブレンドは使わない。** 遅延読み込み（使う作品だけ）。
3. **名前は CSS と同じ（ハイフンつき）。** `softLight` などは警告して案内する（受け付けない）。
4. **普通の合成層に付けたときは「子が別々に混ざる」のまま。** `threeD: true` かフィルタを付けるとまとめて混ざる、と文書に書く。新しい `isolate` の項目は作らない。
5. **`maskInverted` との併用は、原因を調べて直せれば直し、直せなければ警告して通常描画にする。**
6. **高度なモードの層が 10 枚以上同時に出たら 1 回警告する。**
7. **ギャラリーに「光と色」の作品を 1 本付ける**（新しい文脈の作者が文書だけから作る）。
