## 1. 目的

After Effects の「トラックマット」と「ルマワイプ」に当たるものを入れる。今のマスクは **1 つの層に 1 つ、その層の中に書く**。次ができない。

- **同じマスクを複数の層で使う**（動くマスクを 3 層に掛けるには 3 回書き写すしかない）。
- **1 つの層に複数のマスクを掛ける**（交差、引き算）。
- **アルファでなく輝度（ルマ）で切り抜く**（グレースケールの画像、グラデーション）。
- **マスクを掛けた層に `blendMode` を併用する**（0.22 で `maskInverted` だけ直した。テキスト・画像・動画のマスクは警告して逃げている）。
- **輝度マップで切り替わるトランジション**（ルマワイプ）。

やらないこと: マスクの羽根（ぼかし）の専用オプション、`threeD` 層へのマット（警告のまま）、別の合成にあるマットの参照、マット自身へのマット、マットの和（足し算。合成層をマットにすれば今でもできる）。

## 2. 確かめた事実

試作（Opus 級のエージェントが別の作業コピーで実施。私が絵と数字を読み、写した。**再現はしていない**）。測定は Apple M1 Pro のヘッドレス Chrome。

- **方式**: マットを、マットを掛ける層の**フィルタ列に入れる `MatteFilter`** にする。マット層は、合成と同じ大きさのテクスチャに**フレームごとに 1 回**描き（`CompositionSequence.updateSpace` で、そのフレームの状態だけから）、フィルタは `calculateSpriteMatrix`（`DisplacementFilter` と同じ仕組み。フィルタ列のどこに置いても動く）でそのテクスチャを引く。層自身の表示オブジェクトは変わらないので、`zIndex`、`_visual`、`layers()`、寿命の `renderable` 切り替え、`parent`、時間リマップ、フィルタ付きのマットは、そのまま。
- **正しさ**（WebGPU と WebGL）: アルファ、アルファ 0.5、ルマ、反転アルファ、反転ルマ、引き算 `A·(1−B)`、ルマ B との交差、テキストのマット、画像のマット、マットされた層が自前のフィルタを持つ場合の 10 ケース × ブレンド 6 種（normal、multiply、screen、overlay、soft-light、hue）を、`tests/support/blendReference.ts` と比べて**最大 0.68/255**。マットされたテキスト・画像・動画の層も 0.5/255 以内。ルマは Rec.709 の重み（0.2126, 0.7152, 0.0722）を乗算済みの色に掛ける（透明なところは黒として数える）。
- **共有マット**: 1 つのマット（`x`・`width`・`scaleY` を動かす）を 3 層で共有し、6,140 点でマット単体の描画と比べて不良 0、最大 0.38/255。前向き・ジャンプ・後ろ向きのシークで差 0。成長するテキストをマットにしても同じ。**Pixi の「1 つの `Graphics` を複数のマスクに使うと最後の層以外が古くなる」罠は起きない。**
- **コスト**（1080p、全面の層、アルファ 0.6、中央値。WebGL は繰り返しで最大 15% 動く）:

  | ms/フレーム（1 / 3 / 10 層） | WebGPU | WebGL |
  |---|---|---|
  | マスクなし | 0.21 / 0.29 / 0.73 | 0.41 / 0.41 / 0.66 |
  | 今の形のマスク（ステンシル） | 0.12 / 0.16 / 0.32 | 0.28 / 1.36 / 2.77 |
  | 今の `AlphaMask`（`maskInverted`） | 0.45 / 1.10 / 3.89 | 1.29 / 5.19 / 12.6 |
  | **マットフィルタ（層ごとに 1 つ、MSAA）** | 0.32 / 0.75 / 2.65 | 1.22 / 4.03 / 11.0 |
  | **マットフィルタ（1 つを共有、MSAA）** | 0.32 / 0.67 / 1.97 | 1.21 / 3.07 / 7.43 |
  | マット 2 つを層ごとに | 0.41 / 0.91 / 3.01 | 1.84 / 4.92 / 12.9 |

  → マットフィルタは `AlphaMask` より速く、ステンシルより遅い。WebGL ではブレンドのフィルタのほうが、マットより重い。マット 1 つのテクスチャは 1080p で **7.9 MiB**（MSAA のサンプルバッファはその数倍と見積もり。未測定）。
- **縁**: MSAA なしだと、マットの縁がギザギザになる（直接 MSAA のキャンバスに描いた基準と、約 190 画素が最大 128/255 違う）。MSAA ありなら WebGPU でビット一致、WebGL では縁が最大 64/255 違う。
- **ルマワイプ**: 既存のトランジションの仕組みにそのまま入る（`LumaWipeFilter` と `expandLuma`、約 60 行 + 輝度マップの解決）。輝度マップは、組み込みのグラデーション名か `Assets` の名前。WebGL と WebGPU が 0 画素差、シークは決定的。組み込みの放射状マップは 16:9 に引き伸ばされた（次は、シェーダーの中でアスペクト補正をして計算する）。
- **試作が見つけた、本番で要ること**: (1) `parent` を持つマット層は、どの容器の中にもないので、null 層の鎖の変換を手で合成した（null のアルファと `renderable` は未対応）。(2) トランジションで層を包むと、兄弟のマットから離れる（"mask m: no layer"）ので、包む層が名前つきマットを持つようにした。(3) 拡大・回転した入れ子の合成、`threeD` の合成の中のマットは、マットを局所空間に描いて再サンプルするので、縁の画素だけ違う（約 150 画素、最大 100/255）。(4) `threeD` のマット層、`inspect` の範囲のマットによる切り取り、別の合成からの参照は未対応。(5) マットされた合成は、フィルタを持つ合成と同じ扱いで、子のブレンドはそのテクスチャの中で効く。
- **未検証**: 本物の Sprite に置き換える案、MP4 の書き出し、実時間の再生、devicePixelRatio 2、Apple 以外の GPU、マットの和、マット自身がマットされる場合。

## 3. 設計

### 3.1 書き方

`mask` の値を広げる。**層の仕様（`type` を持つもの）はこれまでどおりインライン**、それ以外が「別の層を名前で指す」。

```js
// 名前つきマット: 同じ合成の別の層を名前で指す。その層自身は描かれない。
{ type: 'shape', shape: 'rect', name: 'wipe', anchorX: 0, width: 0, height: 420,
  initial: { x: 60, y: 300 }, keyframes: [{ at: 0.3, to: { width: 560 }, duration: 1.5 }] },
{ type: 'text', text: 'SHARED', mask: 'wipe' },
{ type: 'text', text: 'MASK', at: 0.2, mask: 'wipe' },

// 輝度で切り抜く（グレースケール画像やグラデーションの層）、反転、引き算（B を引く = B の反転を掛ける）
{ type: 'image', asset: 'photo', mask: { layer: 'vignette', channel: 'luma' } },
{ type: 'shape', …, mask: ['panel', { layer: 'hole', invert: true }] }      // panel の中で、hole の外
```

- **`mask: 'name'`** = `{ layer: 'name' }`。`channel` は `'alpha'`（既定）か `'luma'`、`invert` は真偽（既定 偽）。
- **配列は交差**（全部の積）。**引き算は、引く側に `invert: true`**（`maskMode` は作らない: 反転が 1 つの項目で全部を表せる）。
- **名前つきマットの層は、それ自身は描かれない**（マットとして使われている名前の層は画面に出ない）。**マットの時間は合成の時間**（そのマット自身の `at` と `duration`）。マットの寿命が、マスクを掛けた層の寿命を覆わないと、層が見えない区間ができるので警告する。
- **インラインのマスク `mask: { type: …, … }` と `maskInverted` は、書き方を変えない。**
- **`blendMode` は、すべてのマットと併用できる**（マットのフィルタの後に、ブレンドのフィルタが最後に入る）。

### 3.2 仕組み

- **ハイブリッド**: 形（`shape`）の、反転なしのインラインマスクは**今のステンシルのまま**（一番安く、キャンバスの MSAA で縁がきれい、ブレンドも既に効く）。**それ以外はすべてマットフィルタに送る**: 名前つき、複数、ルマ、`maskInverted`、テキスト・画像・動画のマスク（インラインでも）。
- **インラインのマスクがマットフィルタ側に回るとき**は、マスク層を「名前のない、その層専用のマット」として扱う（今と同じ位置・同じ寿命・同じ空間で、フレームごとに 1 回テクスチャに描く）。
- **消えるもの**: `AlphaMask` を使うコード、`erase` のラッパー（0.22）、「テキスト・画像・動画のマスクではブレンドが失われる」警告。ブレンドは、すべてのマットで効く。
- **マットのテクスチャは MSAA あり**（縁のギザギザを避ける）。マット 1 つ 1080p で約 8 MiB + サンプルバッファ。
- **マットの描画**は `updateSpace` の中で、**そのフレームの状態だけから**（前のフレームに依存しない）。非表示のマットは空のテクスチャ（マスクが全部 0 = 層が消える）。
- **ルマワイプ**: トランジションの新しい種類 `{ kind: 'luma', from, to, at, duration, map, softness, flip, ease }`。`map` は `'radial'`・`'linear'`・`'diagonal'`（組み込み。シェーダーの中でアスペクト補正して計算する）か、アセット名（グレースケール画像）。`softness`（既定 0.1）は境目のやわらかさ、`flip` は向きの反転。入ってくる側はやわらかく現れ、出ていく側は硬く消える（既存の `wipe` / `iris` と同じ流儀）。

### 3.3 警告（すべて「警告を出して、無視」。書き方の間違いは作るときに 1 回だけ言う）

名前が見つからない（did-you-mean つき）、同じ名前の層が複数ある（最初のものを使う）、マットの寿命が足りない、`channel` が `alpha` / `luma` でない（`luminance` / `brightness` / `grayscale` → `luma`、`alpha` 以外 → 案内）、`invert` が真偽でない、`maskInverted` を名前つきマットと一緒に書いた（`invert: true` を案内）、マット自身にマスクがある（当面、無視）、マットが `threeD`、マットを掛けた層が `threeD`（今と同じ「`threeD` へのマスクは未対応」）、マスクを掛けた層が `parent` を持つ（マットは合成の空間、層は null 層の空間: null 層にマスクを掛けるよう案内。**ただし、マット層自身が `parent` を持つ場合は、試作のとおり null 層の鎖を合成して動かす**）、マットが多すぎる（1080p で 8 つを超えたらメモリの警告）、`luma` の `map` が見つからない（トランジション。アセット名の did-you-mean）。

### 3.4 `inspect`、タイムライン

- マットとして使われる層は、レイアウトの検査（「サイズなし」「重なり」「画面外」）から外す。マスクを掛けた層の範囲は、**名前つきマットでは切り取らない**（試作が未対応。文書に書く。インラインのマスクは今のまま）。
- タイムライン図では、マットの行に「matte」と表示する（任意）。

## 4. AI 親和性と、共通のパラメータルールとの整合

### 4.1 AI 親和性

| 観点 | 判定 |
|---|---|
| 共有の語彙 | 新しい項目はない。`mask` の値が広がるだけ（名前、`{ layer, channel, invert }`、配列）。AE の「トラックマット」の言葉（alpha / luma / inverted）に揃える |
| よくある使い方は 1 行 | `mask: 'wipe'`、`{ kind: 'luma', map: 'radial' }` |
| 間違いは作るときに直し方つきで警告 | 3.3。名前の打ち間違いは did-you-mean |
| 隠れた規則 | 3 つ: (a) マットとして使われた層は描かれない、(b) マットの時間は合成の時間、(c) 名前つきマットは同じ合成の中だけ。すべて警告か文書の 1 節で見える |
| 使わない人へのコスト | 0（マットを使わない作品は、新しい経路を通らない） |

### 4.2 共通のパラメータルールとの整合

| 共通ルール | 新しい名前の扱い |
|---|---|
| 全層で同じ語彙。新しい小さな言語を作らない | `mask` は既存の項目。層を「名前で指す」のは `parent: 'name'`・`focus: 'name'`・トランジションの `from` / `to` と同じ種類 |
| 固定の設定は最上位、動く値は `initial` とキーフレーム | `mask` / `channel` / `invert` は固定の設定（動かせない。動かしたいときは、マット層の `alpha` や 2 層を使う） |
| 名前の意味は 1 か所で決まる | 同じ名前の層が複数あれば、最初のものを使って警告（`parent` と同じ） |
| 打ち間違い・別名は直し方つきの警告 | 3.3（`luminance` / `brightness` など） |
| エンジン中立の名前 | 「マット」「ルマ」は編集の言葉で、描画エンジンの名前を含まない |

## 5. テスト

- **単体（速い）**: 参照の解釈（`'name'`、`{ layer, … }`、配列、インラインの層との見分け）、警告 3.3 のすべて、マット層が描かれないこと、`inspect` がマットを外すこと、`mask` を使わない層は何も変わらないこと。
- **ブラウザ（実機、WebGPU と WebGL）**: 試作の 10 ケース × ブレンド 6 種を、`blendReference.ts` と **2/255 以内**。共有マットを 3 層で（マットが動くフレームで古くならない）、前向き・ジャンプ・後ろ向きのシークで一致。テキスト・画像・動画のマット。マットの寿命と層の寿命の食い違い。`parent` を持つマット層。トランジションの中の名前つきマット。ルマワイプ（組み込み 3 種 + 画像）。

## 7. リスク

- **インラインのマスクの移行で、既存作品の縁が変わる**。使っている作品は少ない（`ma`、`05-composition-mask`、ほか数本）。前後を数字で比べる。
- **WebGL の縁**: MSAA ありでも、直接描いた基準と最大 64/255 違う縁が残る。気になる作品が出れば、局所の問題として扱う（文書に書く）。
- **メモリ**: マット 1 つ 8 MiB + サンプルバッファ。8 つを超えたら警告。
- **拡大・回転した入れ子の合成、`threeD` の合成の中のマット**は、縁の画素だけ違う（再サンプル）。文書に書く。
- **Pixi の内部への依存**: `calculateSpriteMatrix` と `filter` パイプの使い方に依存。`DisplacementFilter` と同じ仕組みなので壊れにくいが、`pixi.js` 8.22 より前は未検証（ブレンドと同じ）。
- マットされた合成の中の子のブレンドは、そのテクスチャの中で効く（フィルタを持つ合成と同じ）。文書に書く。

## 8. 決めてほしいこと（私の推し付き）

1. **ハイブリッドにする**: 形のインラインマスク（反転なし）はステンシルのまま、それ以外はすべてマットフィルタ（推し）。全部をマットフィルタにすると、速さと縁で損をし、既存の作品への影響も大きい。
2. **引き算は `invert: true`**（推し）。`maskMode` は作らない（保留メモの案を取り下げる）。
3. **ルマの重みは Rec.709**（推し。AE と同じ流儀）。
4. **名前つきマットは、同じ合成の中だけ**（推し）。マットの時間は合成の時間。
5. **ルマワイプは `{ kind: 'luma', map, softness, flip }`**（推し）。組み込み `radial` / `linear` / `diagonal` と、グレースケール画像のアセット。
6. **`threeD` 層へのマット、`threeD` のマット層は、今回も入れない**（警告のまま）。
7. **名前つきマットでは `inspect` の範囲を切り取らない**（推し。文書に書く）。
8. **見せ場の作品を 1 本付ける**（推し）。
