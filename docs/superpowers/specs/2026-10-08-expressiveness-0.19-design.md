# 0.19 表現力の拡張 — 設計メモ

状態: 承認済み・実装済み（0.19.0 の範囲 = 4 章。リリースはオーナーの合図待ち。0.20.0 の骨子は 5 章のまま）。実装での調整は末尾の「9. 実装での調整」。
読む人: オーナー。決めてほしいことは 8 章。
前提: 0.18.0 は公開済み。手元に未公開の `animateText` の警告の修正が 1 件ある（0.18.1 として出す想定）。0.19 の 5 つの項目は、使い捨ての実験（スパイク）で「作れるか・API の形・費用」を調べ済み。実験の報告は、各項目の「分かったこと」にまとめた。

## 1. 目的

AI が書く映像の「できること」を、AE（After Effects）の標準的な道具に近づける。実験で、5 つとも作れると分かった。同時に、**0.19 の 5 つに、先日の事件（`animateText` の `out: { at }` が黙って無視された）から出た 1 つを足す**: 間違ったキーを黙って受け流さない（未知のキー・不正な値への警告）。

やらないこと: 新しい書き出し形式、サーバー、Playground の機能追加、シェーダーの多段（バッファ・フィードバック）。

## 2. 実験で分かったこと（要約）

| 項目 | 作れるか | 目安の工数 | 一番の注意 |
|---|---|---|---|
| スプリングの ease | 作れる（閉じた式、依存なし、約 130 行） | 8〜10 h | ease は 0〜1 の進み具合しか見えない。物理の時間にするには `duration: 'auto'` が要る |
| `fillGradient` のアニメーション（図形・文字） | 作れる（約 145 行）。シークは全フレーム同一 | 8〜10 h | 警告が `onStart` の中だと、シークのたびに繰り返す。ビルド時に検査する |
| 粒状ノイズ（grain） | 作れる（名前付きフィルター、約 170 行）。WebGL と WebGPU が一致 | 6〜8 h | フィルターに「時間」を渡す仕組みが新しい。ルートに掛けると全面の中間パスが 1 本増える |
| シェーダー層 | 作れる（専用の WebGL2 キャンバスをスプライトにする。シーク差 0） | 14〜20 h | **映画は WebGPU を先に使うので、Pixi のフィルターとしては動かない**。GPU の暴走（無限ループ）は防げない |
| マスクの共有・複数 | 一部。共有は「層ごとに同じ指定の複製」で可。引き算はテクスチャ経由なら可 | 25〜35 h（再見積もりが要る、下記） | Pixi の同じ Graphics を複数のマスクに使うと、動かしたとき最後の層以外が古いまま |

実験で出た事実で、設計に効くもの:

- **スプリング**: 例の `spring(1,170,26)` は臨界減衰（減衰比 0.997）で、オーバーシュートしない。弾ませたいなら、剛性 170 で減衰を 20 未満にする。プリセット名（`spring.gentle` / `snappy` / `bouncy` / `wobbly` / `slow`）を先に教えれば、AI が数値を手で調整しなくて済む。色は OKLab のチャンネルが 0〜1 に切られ、alpha は 1 を超えると切られる。
- **`fillGradient`**: stops の色は、層の `colorSpace` に従わせないと、途中が濁る（sRGB だと灰緑になった）。スプライトの下地は 256 px だと、1920 px 幅の硬い境目で少しぼける（512 にするか設定にする）。アニメする図形 50 個で 1 フレーム約 9 ms（ソフトウェア GL、1080p）。毎フレーム新しい `FillGradient` を作る素朴な方法は約 19 ms で、リークする。
- **grain**: 既存の `noise` は粒状ノイズではない（種が `Math.random()` なので実行ごとに違う、1 枚の固定パターン、サイズ指定なし、黒が持ち上がる）。放物線の重み（4L(1−L)）で平均輝度のずれは 0.02% 以下になる。整数ハッシュなので、どの GPU でも同じ絵になる。
- **シェーダー**: WebGL2 の専用キャンバスなら、マスク・フィルター・2.5D がそのまま効く。エラーは自分でコンパイルして、利用者の行番号で出せる（`#line 1`）。
- **マスク**: 実験が見つけた 2 つの不具合（text のマスクが長方形になる、`maskInverted` が外のマスクからはみ出す）は、**0.17.0 で直した**。つまりテクスチャ経由の道（`AlphaMask`）は、もう入っている。実験の見積もり（25〜35 h）は、これが無い前提なので、**計画の段階で再見積もりする**。

## 3. 提案: 二つの版に分ける

全部で約 60〜85 時間分あり、種類も違う（動き・色の仕上げと、層・合成の仕組み）。0.17・0.18 と同じ大きさで 1 版ずつ出すために、二つに分ける。

- **0.19.0 「動きと色」**: スプリング、`fillGradient` のアニメーション、grain、**未知のキー・不正な値への警告**。合計 約 30〜36 h。どれも既存の層・フィルターの内側で完結し、互いに独立。
- **0.20.0 「層と合成」**: シェーダー層、マスクの共有（名前付きマット `mask: 'name'`、複数の交差・引き算）。仕組みを足す版で、実機（GPU）での確認が要る。

その前に **0.18.1**（手元の `animateText` の警告）を出す。

## 4. 0.19.0 の設計

### 4.1 スプリングの ease

- 書き方: `ease: 'spring(質量, 剛性, 減衰)'`（省略時 1, 100, 10）。プリセット `spring.gentle` / `snappy` / `bouncy` / `wobbly` / `slow`。キーフレームの `duration: 'auto'` は「そのバネが落ち着くまで」。
  ```js
  { at: 0.2, from: { y: -200 }, to: { y: 0 }, duration: 'auto', ease: 'spring.bouncy' }
  { at: 0,   to: { scale: 1 }, duration: 0.8, ease: 'spring(1, 170, 12)' }
  ```
- 作り: `src/core/spring.ts`（閉じた式。過減衰・臨界・不足減衰。落ち着く時間は 0.5% 以内に入り続ける時刻を二分法で求める）。GSAP の `registerEase('spring', fn)`（`fn.config(m,k,c)`）と、プリセットの登録。`Movie` と `presets/_ease.ts` から登録し、stagger や cameraPath でも名前が通る。キーフレームの `duration` を読む 5 か所を `kfDuration(kf)` に替える。
- 決めごと: 明示した `duration` のときは、形は減衰比だけで決まる（`duration` が落ち着く時間になる）。質量と剛性が効くのは `'auto'` のときだけ。文書は「本物の物理なら `'auto'`」と書く。`'auto'` を spring でない ease に使ったら警告（試作は 0.5 s に落ちていた）。`stagger()` の遅れにスプリングを使うと範囲外になるので、0〜1 に切る。`animateText` と `orbit` の tween は文字列の ease をそのまま GSAP に渡すので使える。数値の `duration` のままなので `'auto'` は対象外（一言書く）。
- 検査: 0.17 の `checkEase`（存在しない ease への警告）を `spring(` の書式の誤りまで広げる（`spring(1, 170` や `spring.floppy`）。警告は `config` の中ではなく `checkEase` で 1 回だけ出す（GSAP が壊れた入力で `config` を層ごとに呼ぶため）。
- テスト: 両端が 0 と 1、後ろ向きの掃引が前向きと同一、GSAP のタイムラインの往復、落ち着く時間、独立した Euler 積分との一致。実ブラウザでシークの同一性。
- 見せ場の作品: スプリングで動くものを 1 本（UI のマイクロインタラクションの作り直しが向く）。

### 4.2 `fillGradient` のアニメーション

- 書き方: **1 つの `fillGradient` オブジェクトのまま**、キーフレームの `set` / `from` / `to` に**部分オブジェクト**を書く（`angle`、`center`、`innerRadius`、`radius`、`stops`）。数値は線形に補間し、stops の色は層の `colorSpace` で補間する。書かなかったキーは今のまま。`stops` の個数は変えられない。
  ```js
  fillGradient: { angle: 0, stops: [[0, '#ff2d55'], [1, '#0ea5e9']] },
  keyframes: [{ at: 0, duration: 2, to: { fillGradient: { angle: 360, stops: [[0, '#00e5ff'], [1, '#ffd60a']] } } }]
  ```
  文字の層にも同じ書き方を使う。
- 作り: `src/sequences/gradientAnim.ts`（`tweenGradient`、`mergeGrad`、`bindGradientKeyframes`、層ごとに 1 つの `GradientPainter`: 256² の canvas と Texture を同じものに描き直す）。キーフレームが `fillGradient` を含むときだけこの道に入り、含まない図形は今の静的な道のまま。`Shape.ts` に約 25 行、`Text.ts` に約 12 行。
- 決めごと（実験からの変更）:
  - **警告は `onStart` ではなくビルド時に出す**（シークのたびの繰り返しを避ける）。個数が違う stops、キーの typo（did-you-mean）、初期値が無いのにキーフレームが `fillGradient` を持つ、`'fillGradient.angle'` や `gradientAngle` のような AI が推測する名前（「`fillGradient: { angle }` と書く」と教える）。
  - 下地は **512²** にする（硬い境目が荒れる）。
  - 静的と動的の二つの描き方は、既存テストのピクセル比較で同じになることを確かめて、1 本の道（canvas）にまとめる。
  - 数値の色（`0xff0000`）が補間で壊れる点は、`fillColor` の補間も同じ恐れがあるので**確かめて、あれば直す**（実験は未検証）。
- テスト: 前向き・ジャンプ・後ろ向きで全フレームが同一、色空間ごとの途中の色、警告の各種。ギャラリーとポスターのピクセルが変わらない。

### 4.3 grain（粒状ノイズ）

- 書き方: 名前付きフィルター `grain`（`amount` 既定 0.08＝中間灰での標準偏差、`size` px 既定 1.5、`seed`、`fps` 既定 24（0 で静止）、`color` 0〜1 既定 0）。層にもルートの `filters` にも付く。
  ```js
  composition: { sequences, filters: [{ type: 'grain' }] }                       // フィルムの質感を 1 行で
  { type: 'image', asset: 'photo', filters: [{ type: 'grain', name: 'g', fps: 12 }], keyframes: [{ at: 3, to: { 'filters.g.amount': 0.2 }, duration: 2 }] }
  ```
- 作り: `src/filters/Grain.ts`（整数ハッシュ、GLSL ES 3.00 と WGSL、プロパティの getter / setter でキーフレームが通る）。`named.ts` に 3 行。**時間の渡し方**: ムービーが持つフィルターの一覧を、`Sequence.buildFilters` で集め、`_renderNow` が `setTime(t)` を持つフィルターに渡す（試作の「ステージの木を歩く」はやめる）。
- 決めごと: 放物線の重み（平均を保つ）。整数ハッシュ（どの GPU でも同じ絵）。`noise` はそのまま残し、文書に「固定・種なし・黒を持ち上げる」と書く。重ねるだけの層（案 b）、ビネット、ハレーションは入れない。
- 未確認で、実装中に測る: 実 GPU での速さ、mp4 / webm の書き出し、`filters.g.amount` のキーフレーム、モーションブラーの副フレームが 1 つの粒の絵を共有すること、30 fps の中の 24 fps の粒の拍。文書に「粒は H.264 のビットレートを食う。上げる」と書く。
- テスト: 粒の分布（標準偏差、平均）、シークの同一性、種の独立、WebGL と WebGPU の一致、ルートに掛けた場合の全面パス。

### 4.4 未知のキー・不正な値への警告（新）

事件の原因（`out: { at }` が黙って捨てられた）と同じ種類の穴が、層のほぼ全体にある（`bogus: 1` も `fontSize: 'nope'` も黙って通る）。AI は警告を指示として読むので、効果が大きい。

- 範囲: (a) 層の仕様のキー（`type` ごとの表）、(b) キーフレームの `to` / `from` / `set` のプロパティ名（GSAP の「Invalid property」だけが今の唯一の手がかり）、(c) `style` のキー、(d) 数値か式のはずの値（`'nope'`）。警告は例外にしない。did-you-mean を付ける（`suggestName`、`warnUnknownOptions` を再利用）。
- 作り: `src/core/lint.ts` に `lintKeys(spec)` を足す。キーの表は型から作れないので、**表と型が食い違わないテスト**を置く（型の全キーが表にある）。
- 最大の危険: **偽の警告**。ギャラリー 39 作品、ガイドの例、レシピ、`examples/` の全部が、新しい警告を 1 つも出さないことをテストにする（これが合格条件）。表にないキーを使う利用者が出るので、メッセージは「`<key>` は <type> 層のキーではありません（候補: …）」と、何が正しいかを言う。
- 見送り: 値の範囲の検査（alpha が 1 を超える、など）は、意図があることが多い。入れない。

## 5. 0.20.0 の設計（骨子。0.19.0 の後で、改めて設計メモを書く）

- **シェーダー層**: `{ type: 'shader', fragment, uniforms, resolution, transparent }`。Shadertoy の 1 パス（`mainImage`）。層ごとに WebGL2 キャンバスを持ち、そのキャンバスを 1 つのスプライトのテクスチャにする（本番は、ページ全体で 1 つの GL コンテキストを共有する。Chrome の約 16 個の制限を避けるため）。組み込み（`iTime` など）は宣言を自動で足す。uniform は数値・ベクトル・色で、通常のキーフレームで動く。コンパイルエラーは利用者の行番号で警告し、層は目立つ市松模様を描く。シークは `iTime` が層のローカル時間で決まるので差が出ない。**入れないもの**: 多段、フィードバック、背後の層を読むフィルターとしての使い方。**注意**: GPU の暴走は防げない（ループの上限を文書に書き、`while` と上限が定数でない `for` に警告）。GPU が違うとピクセルは同一にならない（同じ機械では決定的）。
- **マスク**: 名前付きマット `mask: 'name'`（AE のトラックマット）、複数マスクの交差（既定）と引き算（`maskMode: 'subtract'`）。`add` は入れない（合成をマスクにすれば今でも足せる）。共有は「層ごとに同じ指定の複製」、引き算はテクスチャ経由。**0.17.0 で `AlphaMask` が入っているので、再見積もりする**。今すぐ文書に書けること: ヌル層に `mask` を付けて子に `parent` を指す方法（制限つき）。

## 6. テスト・確認の共通の考え方

- どの項目も、実ブラウザで「前向き・ジャンプ・後ろ向きのシークが同一」を確かめる（決定的な時間の原則）。
- ギャラリーの既存作品のピクセルが変わらないこと（特に `fillGradient` の道の統一と、警告の追加）。
- 速さは測って書く（ソフトウェア GL の値と、実 GPU の値を分けて）。
- 作品: 各機能に、見せ場の作品を 1 本ずつ（設計された作品であること）。

## 7. リスク

- 偽の警告（4.4）。合格条件のテストで抑える。
- スプリングの `'auto'` の誤解。文書と警告で補う。
- grain の実 GPU・書き出しの未測定。実装の中で測る。
- シェーダーの GPU 暴走、WebGL1 の古い環境、GPU 間の差（0.20.0 で扱う）。

## 8. 決めてほしいこと（私の推し付き）

1. 0.19 を **0.19.0（動きと色）と 0.20.0（層と合成）に分ける**（推し）か、全部を 0.19.0 に入れるか。
2. 先に **0.18.1**（`animateText` の警告）を出す（推し）か、0.19.0 に含めて出すか。
3. スプリングは、**`duration: 'auto'` を文書の標準の使い方にする**（推し）。
4. 未知のキーへの警告の範囲は、**層のキー・キーフレームのプロパティ名・style のキー・数値の値（4.4 の a〜d）**（推し）か、層のキーだけか。**例外にはせず、警告だけ**（推し）。
5. grain は**名前付きフィルターだけ**（推し）。重ねる層、ビネット、ハレーションは入れない。
6. 各機能に**見せ場の作品を 1 本**ずつ付ける（推し）。数が多ければ、0.19.0 は 2 本（スプリングと grain の組み合わせ、グラデーションの文字）でもよい。
7. 0.20.0 の順は、**マスクを先、シェーダーを後**（推し: マスクは 0.17.0 の土台があり、シェーダーは実 GPU の確認が要るので後に回す）か、逆か。

## 9. 実装での調整（0.19.0）

- **数値の色の補間のバグを見つけて直した。** `fillColor: 0xff0000` を `rgb` で補間すると、色ではなく数として補間され、赤→緑の途中が黄緑（0x7fff80）になっていた（オリーブにならない）。`tweenColor` が CSS 文字列として補間する（`tests/expr/colorTween.test.ts`）。
- **静的な `fillGradient` と動く道は、2 本のまま残した。** 6 種のグラデーションを両方で描いて比べると、放射状と硬い境目は同一（最大 1/255）、線形は 0.08〜0.17% のチャンネルが 2/255 を超えて違った（最大 35、角丸の縁）。計画の基準（0.1% 以下）を超えたので統一しない。
- **警告はビルド時に 1 回** （`validateGradientKeyframes`）。シークで繰り返さない。`kfDuration` の `'auto'` は、壊れた spring には（`checkEase` が言うので）重ねて警告せず、spring でないときは ease 名ごとに 1 回。
- **grain の時間は、ビルド後に 1 回集めた一覧**（`collectTimeFilters`）を `_renderNow` で渡す。計画の「`Sequence.root` に登録」は、`Sequence.root` が合成の形（幅と高さ）で、ルートの層ではないので成り立たなかった。
- **WebGL と WebGPU の grain は、値の差が最大 1/255（0.02%）で、パターンは同一。** 計画の「0.01% 以下」は試作の 1080p の値で、640×360 では丸めの差が出る割合が違った。
- **4.4 の (d)（`'nope'` のような数でも式でもない値）は外した。** ライブラリは既にビルド時に「expression failed: nope」と警告する。0.18 の振り返りで「`fontSize: 'nope'` が黙って通る」と言ったのは、私の実験の誤り（置換の結果、後ろの `style` キーが勝っていた）で、訂正する。
- **キーの警告が、実際の誤りを 3 つ見つけた。** `hanabi-night`・`orbit-rig`・`shape-shift` の `pitch` が層の直下にあり、無視されていた（正しくは `sfx: { preset, pitch }`）。3 作品を直した（音が変わる）。私の新しいグラデーションの文書とレシピも、`anchorX` を `initial` の外に書いていて、同じ警告で見つかった。
- **測った値:** グラデーション 50 図形のアニメ 10.6 ms / フレーム（平らな色 2.8、静的 2.4。1080p、実 GPU、小さなスナップショットの読み戻し込み）、文字 10 本 10.1 ms（単色 6.1）。grain は 1080p で なし 2.2 ms、モノ 2.8、色 4.5、`noise` 2.5。3 s の平らな 720p の mp4 は、grain なし 6.9 KB、`amount` 0.03 で 9.3 MB、0.08 で 22.3 MB。スプリングのプリセットは 0.42 / 0.72 / 1.08 / 1.29 / 1.61 s で落ち着き、ピークは 1.01 / 1.02 / 1.28 / 1.00 / 1.40。
