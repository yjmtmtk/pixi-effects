# 0.20 時間リマップ（速度・逆再生・静止・合成層の時間）と cubic-bezier — 設計メモ

状態: **承認済み・実装済み**（未リリース）。計画: `docs/superpowers/plans/2026-10-08-time-remap-0.20.md`。実装で変えたことは、末尾の「実装での調整」。
読む人: オーナー。決めたことは 8 章。共通のパラメータルールとの突き合わせは 4.2。
前提: 0.19.0 まで公開済み。**0.20.0 の中身は、この版で「時間」に変わった**（以前の 0.20 案「マスクの共有・複数」は優先度を下げて残す: `2026-10-09-masks-0.20-design.md`）。ロードマップの全体は 9 章。

オーナーが 4 点を承認済み（「オススメでゴー」）:
1. 0.20 を「時間」にする。
2. 音程は第一版では**テープ式**（速度に音程がついてくる）。タイムストレッチは後回し。
3. `speed` と `time` を、映像・音・合成層に入れる。
4. `cubic-bezier` イージングを 0.20 に同梱する。

## 1. 目的

何でも作れるようにする、の中で、時間の扱いが一番欠けている。いまは次ができない。

- **映像の速度を変える**（スロー、早送り、逆再生、一瞬止める、加速して減速する）。
- **「ひとかたまりの動き」の時間を変える。** 合成層（シーケンスのまとまり）を、逆再生、スロー、静止、ループ、加速で使い回せない。AE の「プリコンポーズの時間リマップ」に当たる。
- **音もそれに付いてくる。**
- 動きのカーブに `cubic-bezier(.4,0,.2,1)`（CSS と同じ）が使えない。

やらないこと: タイムストレッチ（音程を保ったままの速度変更）、フレームのブレンド（オプティカルフロー、スローのなめらか補間）、`loop` の再設計、画像・文字・図形層への `time`（合成層に入れて、合成層をリマップする）。

## 2. 確かめた事実

使い捨ての試作（約 200 行の変更 + 新規 129 行の `remap.ts`。作業コピーは `.claude/worktrees/agent-a88a4f163a1e7673d`、本番には持ち込まない）での測定。

**映像（速度 2 / 0.5 / 0.37 / -1、加速、静止、繰り返し、往復の 9 ケース）**
- シーク順序（前進、後ろ向き、ランダムなジャンプ 2 通り、各 26 フレーム）の間で、ピクセル差は**全ケースで 0**。
- 同じファイルを階段状に引いた基準と比べて、6 ケースで 60 フレーム中 60 枚が一致。
- 書き出した mp4 を読み戻して 5 フレームを比較: 平均の絶対差 3.5〜4.3（H.264 の損失）。誤ったフレームだと 8〜124。
- 逆再生のデコードは前進と同じ速さ（720p で 30.6 対 34.5 ms/フレーム）。ただし GOP 30 の短い素材だけで測った。

**合成層（8 機能 × 4 種の時間マップ = 32 通り）**
- 機能: `from` / `fromTo` / `to`、色、テキストの `set`、グラデーション、粒子、spring、入れ子の映像、grain。時間マップ: 速度 2、-1、0.5、ループ + 静止 + 逆向き加速。
- シーク順序の間で差は 32 通りすべてで 0。リマップなしの基準との比較は 30 通りでピクセル一致。残り 2 つ（粒子 0.5 倍、spring 2 倍）は、アンチエイリアスの縁の数ピクセルが違う（最大差 59/255）。GSAP が時計を約 1e-8 秒に丸めるため。シーク順序には依存しない。
- `threeD` とカメラ（キーフレーム、区間つき）、`threeD` で回る合成層、入れ子のリマップ（2 倍の中の -1 倍）、`at: 2` の合成層: すべて差 0（各 20 フレーム）。モーションブラー: 差 1/255。
- 追加の負荷: 200 層で 1 フレーム 0.01 ms 未満。静止中は中身の描画を省ける。初期化は変わらない（24〜26 ms）。
- 既存のテスト: 単体 1730 件、ブラウザ 204 件が、試作でも通った。

**音（200→1000 Hz のチャープと 440 Hz の映像音で、ゼロ交差の周波数を測定）**
- 速度 2: 840 / 1640 Hz（期待 840 / 1640）。速度 0.5: 160 / 250（期待 152 / 253）。速度 -1: 890 / 390（期待 890 / 390）。3 次の加速: 中間で 1750 Hz（期待 1800）。静止: RMS 0.000。映像音は速度 2 で 880 Hz、速度 0.5 で 220 Hz。
- 速度 -1 の合成層の中の音、速度 2 の合成層の中の映像音も、時計に付いてきた。
- 描画コストは 1 層あたり 30 ms 未満。
- ネイティブの `playbackRate` は逆再生も、サンプルごとのワープもできないので、試作では JS のリサンプラーを足した。
- 未検証: 効果音の合成音（`sfx` / `music`）をこの経路に通した場合、`loop` との併用、WebGPU、Safari。

**試作が見つけた、本番で直す必要のあること（今の挙動の不具合を含む）**
1. 合成層の `from` / `to` の開始値は、最初に描画された瞬間に取られる。リマップした合成層に、**後ろ向きから先にジャンプすると、誤った開始値が固定される**（粒子のループで最大差 239）。直し方: 作るときに `inner.time(end); inner.time(0)` を 1 回通す（5 行。メイン側の Movie が既にやっていること）。
2. 子の `duration` の既定は合成層の長さ。速度が 1 より大きいと、`duration` 秒より後ろの中身が消える。直し方: 中身の長さ `contentLength = max(duration, |speed| × duration, `time` の最大値)` を子の既定にする（15 行）。**これが唯一の隠れた規則**（4 章）。
3. カメラの区間、`updateSpace`、`compEnd` が全体時間を使っていた。時計の時間を渡し直す（6 行）。
4. grain の時刻が全体時間で一つだった。リマップした合成層の下では、その時計を渡す（10 行）。
5. `Movie._awaitVideoFrames` が `t - absoluteStart` で局所時間を求めていた。リマップした合成層の中では誤る。映像側が「タイムラインが最後に書いた値」を持つ形に替える。
6. **映像フレームのキャッシュ鍵が 1 ms に丸められている**（`Math.round(t × 1000)`）。別々の時刻が同じ鍵に衝突し得て、結果が先に走った要求に依存する。試作は 1e6 に変えた。**実際に衝突するかは未確認**。全動画に影響する変更なので、本番では独立した手順にして、前後で既存の作品がピクセル一致することを確かめる。
7. k/30 のようなフレーム境界の時刻が、浮動小数点の誤差で 1 枚手前のフレームを選ぶ（静止と往復の 60 サンプル中 20〜40 枚）。5e-5 秒の補正で解消した（60/60）。

## 3. 設計

### 3.1 書き方

時間を、**`time` という普通のキーフレーム項目**にする。その層の中身の秒数で、映像と音では元素材の位置、合成層ではその中の再生ヘッドになる。`speed` は `time` を一本の直線で動かす略記。

```js
// いちばん簡単: 速度だけ（負なら逆再生）
{ type: 'video', asset: 'clip', duration: 4, speed: 0.5 }                       // スロー
{ type: 'composition', duration: 4, speed: -1, sequences: [ … ] }               // 中身を逆再生

// 難しい: time をキーフレームで動かす（いつもの at / duration / ease / repeat / yoyo / from / to / set）
{ type: 'video', asset: 'clip', duration: 5, keyframes: [
  { at: 0, from: { time: 0 }, to: { time: 2 }, duration: 1 },                   // 1 秒で 2 秒分進む
  { at: 1, to: { time: 2 }, duration: 0.5 },                                    // 静止（同じ値へ）
  { at: 1.5, to: { time: 6 }, duration: 3.5, ease: 'power2.inOut' } ] }         // 加速して減速
```

- **対象:** `video`、`audio`、`composition` の 3 種。ほかの層で書くと警告して無視（合成層に入れて、合成層をリマップするよう案内）。
- **`speed`:** 0 以外の数。負は逆再生。**開始位置は `|speed| × duration`**（つまり `speed: -1` は元の最初の `duration` 秒を逆向きに再生）。ほかの開始位置は `initial: { time: … }` で決める。
- **静止:** 同じ値への 2 本のキーフレーム。**ループ:** `repeat`。**往復:** `yoyo`。**新しい概念は足さない。**
- **`speed` は固定の設定**（`loop` や `volume` と同じく**最上位**に書く。変わる開始値だけが `initial`）。速度を時間の途中で変えたいときは、`speed` ではなく `time` のカーブを書く。`initial` やキーフレームに `speed` を書いたら、警告してそう案内する。
- **`time` の単位は秒。負の値は「中身の終わりから」**（`at` や `poster` と同じ共通ルール。映像は元ファイルの長さ、合成層は中身の長さ）。例: `time: -2` は終わりの 2 秒前。
- **`speed` と `time` のキーフレームを同時に書いたら:** `time` が勝ち、`speed` は無視して警告。
- **映像の `loop`:** 元の長さで折り返す（`v % 元の長さ`、負の値も正しく折り返す）。ループしないときは、ファイルの範囲で止める。
- **合成層に使うとき、決まりは 3 つ**（隠れた規則なので 4 章で見える化する）:
  1. 合成層の中の子の `at / duration / keyframes` は、**その合成層の局所時間**で書く。
  2. リマップした合成層**自身**の x や alpha などのキーフレームは、AE と同じく**外側の時間**のまま。
  3. 子の `duration` の既定は「中身の長さ」（2 章の 2）。

### 3.2 仕組み

- **時計:** 層ごとに時計の値（`time`）を持つ。時計を GSAP のキーフレーム機構（`applyKeyframes`）で動かし、`time` 以外のキーフレームは今までどおり表示オブジェクトに掛ける。`time` の置き換えは `remap.ts`（新規）の `timeRemapOf` が担う。
- **映像:** 時計は既存の `currentTime` そのもの。フレームの検索 `_lookup(v)` を、ループは剰余、そうでなければ範囲内に収める。
- **合成層:** 子を**局所時間（オフセット 0）で、一時停止中の専用タイムライン**に作り、時計の setter が `inner.time(v)` を呼ぶ。時計のトゥイーンは親のタイムラインに置く。入れ子のリマップは自然に合成される。同じ値なら再描画しない。静止中は中身の描画が止まる。
- **音:** `AudioDescriptor` に省略可能な項目を 2 つ足す。`warp`（映像の時間 → 合成層の局所時間）と `sourceMap`（その時間 → 音の中の位置）。ミキサーは、この 2 つがあるときだけサンプルごとの線形補間で読む（リマップしていない音は今までの道のまま）。音量のキーフレームは JS で評価する。2 つの写像は、使い捨てのタイムラインを 1 ms ごとに標本化した表（`clockTable`）から作るので、**絵と音が同じキーフレームを見る**。
- **`cubic-bezier`:** `spring.ts` と同じく `gsap.registerEase('cubic-bezier', …)` に `.config(x1,y1,x2,y2)` を持たせる（GSAP が文字列を `(` で分ける）。GSAP 3.15 と 3.12.5 の両方で動く。解法はニュートン法 + 二分法の予備で、1 回 33〜37 ns。Chrome 自身の CSS イージングとの最大差は 4.3e-6（19 本の曲線、行き過ぎと縮退を含む）で、GSAP の CustomEase（9.8e-4）より小さい。引数の個数が違う、x が 0〜1 の外、などは警告する。CSS の `ease / ease-in / ease-out / ease-in-out` は後で足してよい。

### 3.3 警告（すべて「警告を出して、無視」。書き方の間違いは作るときに 1 回だけ言う）

- `speed` / `time` を対象外の層に書いた（合成層に入れるよう案内）。`speed: 0`（静止は `time` を同じ値へ、と案内）。`speed` と `time` のキーフレームの併用。`time` が数でない。
- キー名の打ち間違い（`spped`）: `layerKeys` の表に `speed` / `time` を入れ、did-you-mean が働く。
- **別名の言い換え:** `playbackRate` / `timeScale` / `rate` → `speed`、`timeRemap` → `time`、`reverse: true` → `speed: -1`（`COMMON_ALIASES` に入れ、どう直すかを言う）。
- `initial` やキーフレームに `speed` を書いた（上の説明）。
- `sfx` / `music` の層に `speed` / `time`（効果音の高さは半音単位の `pitch` で変える、と案内。合成音を時間ワープに通す道は、第一版では作らない）。合成層の中の `sfx` / `music` は、合成層のワープに従う（テストで確かめる）。
- 子の `at` が、時計が届く範囲の外にある（約 1 時間）。
- 試作で見つかった**同じ誤りへの重複した警告**（`speed` を図形層に書いたとき、2 回出る）は、直す。

### 3.4 `inspect`、タイムライン

- `timelineData()` の行と `inspect` のトランジション窓は、いま外側の時間で出る（0.5 倍の合成層の 1〜2 秒の子が、実際は外側の 2〜4 秒）。**局所時間の行には「×0.5, local」のように印を付け、外側の時間も併記する**（約 2 時間）。AI が「隠れた規則」に気づけるように、`review()` でも同じ印を出す。

## 4. AI 親和性と、共通のパラメータルールとの整合

### 4.1 AI 親和性

| 観点 | 判定 |
|---|---|
| 共有の語彙 | `time` は普通の項目で、`at / duration / ease / repeat / yoyo / from / to / set` と spring が、そのまま使える。新しい小さな言語はない |
| よくある使い方は 1 行 | `speed: -1`、`speed: 0.5`。複雑な場合も同じキーフレームの形の延長 |
| 間違いは作るときに直し方つきで警告 | 3.3。`layerKeys` の表に載せる |
| 隠れた規則 | 3 つ（3.1 末尾）。`timelineData()` / `review()` の「local」印と、ガイドの 1 節で見えるようにする |
| 使わない人へのコスト | 0（`speed` / `time` を書かない層は、今までの道を通る） |

簡単な例と難しい例は 3.1。

### 4.2 共通のパラメータルールとの整合

既存のルール（`docs/philosophy.md` の「全層で一つの語彙」、チートシートの Conventions 表）に、新しい名前を一つずつ突き合わせた。

| 共通ルール | 新しい名前の扱い |
|---|---|
| 全層で同じ語彙。新しい小さな言語を作らない | `time` は普通のキーフレーム項目。`at / duration / ease / repeat / yoyo / from / to / set` と spring がそのまま使える。`cubic-bezier` は `spring` と同じ「文字列のイージング」の仲間で、CSS と同じ書式 |
| 時間の単位は秒 | `time` も秒。`speed` は単位のない倍率（`scale` と同じ。1 = そのまま） |
| 時間で負の値は「終わりから」（`at`、トランジションの `at`、`poster`） | `time` の負の値も「中身の終わりから」。`speed` の負は向き（逆再生）で、`scale: -1` が反転なのと同じ別の意味 |
| 固定の設定は最上位（`loop`、`volume`）、動く開始値は `initial` | `speed` は最上位。`time` は `initial` とキーフレーム。`speed` の途中変更は `time` のカーブで書く |
| 数は式の文字列でも書ける（ビルド時のみ） | キーフレームの `time` は、既存の数値の経路に乗るので式が使える。最上位の `speed` を式にできるかは未確認（計画の最初に確かめ、使えないなら警告か対応を決める） |
| `duration` は層の寿命（外側の時間）。既定は親の長さ | **変えない。** リマップしても `duration` は外側の寿命。変わるのは中身の長さだけ（`contentLength`、3.1） |
| 無限の繰り返しは書かせない（タイムラインに固定の長さが要る） | 時間のループは有限の `repeat`。映像・音の `loop` は今までどおり（元の長さで折り返す） |
| 名前の意味は 1 か所で決まる | `particles` の `speed` は発射速度（px/秒、プリセットのオプション）で、層のキー `speed`（時間の倍率）とは別の場所。取り違えの言い換えは警告で案内し、文書にも 1 行書く |
| 効果音の高さは半音単位の `pitch` | 音の `speed` はテープ式で音程もついてくる（ファイルと映像音のみ）。`sfx` / `music` には警告して `pitch` を案内 |
| 打ち間違い・別名は直し方つきの警告 | `layerKeys` の表と `COMMON_ALIASES`（3.3）。`speed` を型に足すと、`Covers` 型がビルドで表の更新漏れを教える |

この版では入れないが、共通ルールとの差として記録しておく: 映像・音にある `loop` が、合成層にはない。合成層の `loop` は「繰り返しの周期はどこか」を決める必要があるので（映像は元ファイルの長さ）、有限の `repeat` で書ける今回は見送る。

## 5. テスト

- **シークの同一性**（前進、ジャンプ、後ろ向き、ランダム順）: 映像 9 ケース、合成層 8 機能 × 4 マップ。ピクセル差 0。リマップなしの基準との比較は、GSAP の丸めによる縁の数ピクセルのずれを許す許容値つき（最大 59/255 で、全体の画素比で上限を決める）。
- **映像の階段状の基準**との一致、`Movie.render()` の書き出しを読み戻した比較。
- **音**: チャープのゼロ交差で、速度 2 / 0.5 / -1 / 加速 / 静止、合成層の中の音と映像音。**未検証の 3 つ**（合成音 `sfx` / `music`、`loop` とリマップ、折り返しノイズ）を追加する。リマップしていない音は**今までとバイト単位で同じ**であること（既存の作品全部で）。
- **既存作品の不変:** ギャラリー 41 作品とガイドの例が、ピクセルも警告も変わらない（前後でポスターのフレームを比較）。映像のキャッシュ鍵の変更前後の比較を含む。
- **警告:** 3.3 のすべて（別名の言い換え、`initial` / キーフレームの `speed`、`sfx` / `music` への `speed`）。`cubic-bezier` の許容誤差（1e-4）を CSS の `getComputedTiming().progress` と比べる。
- **負の `time`（終わりから）:** 映像と合成層で、`time: -2` が終わりの 2 秒前と同じ絵になる。範囲を超える負の値は、先頭で止まる。
- **共通ルールの表（4.2）の各行**を、`layerKeys` の表と文書（チートシートの Conventions 表に「層の中の時間」の行を足す）が揃っていることで確かめる。
- **速さ:** 200 層でリマップあり/なしのフレーム時間を測って、文書に書く。

## 6. 手順（計画の骨子）

1. 映像のキャッシュ鍵と、フレーム境界の補正（単独の手順。既存の作品がピクセル一致すること）。
2. `remap.ts` と映像の `speed` / `time`、警告、`layerKeys`。
3. 合成層のリマップ（局所時間のタイムライン、開始値の初期化、`contentLength`、カメラ・`updateSpace`・grain の時計）。
4. 音（`warp` / `sourceMap`、ミキサーのリサンプラー）。
5. `timelineData()` / `inspect` / `review()` の印、範囲外の子の警告。
6. `cubic-bezier`。
7. 文書（チートシート、レシピ、落とし穴、`llms-full`、ガイド 1 節）、プレイグラウンドのプリセット、見せ場の作品 1 本（企画は計画の段階で、先に設計する）、CHANGELOG。

工数の見積もり: 試作の見積もり 16〜20 時間（クリーンアップ 4、inspect とタイムライン 2、警告 1、テスト 5、文書 3、作品とプリセット 3、余裕 2）+ `cubic-bezier` 約 2 時間 ＝ **約 18〜22 時間**。タイムストレッチは含まない。

## 7. リスク

- **映像のキャッシュ鍵の変更は全動画に効く。** 1 の手順で切り分け、既存の作品でピクセルが変わらないことを確かめる。
- **GSAP の丸め**による縁の数ピクセルのずれは、リマップなしとの比較にだけ出る。テストは許容値つきで書く。
- 時計の表（`clockTable`）は、リマップした層ごとに、タイムラインの 1 秒あたり 1000 個の倍精度数を持つ（10 分で約 600 KB）。長尺で数が多いときの測定が要る。必要なら標本化の間隔を粗くする。
- リマップした合成層は、タイムラインを 2 本持つので、`destroy()` で内側も確実に殺す。
- 非単調な長いマップで、映像のデコードがランダムアクセスになる。逆再生の数字は GOP 30 の短い素材のもの。長い GOP の素材での測定が要る。
- 2 倍を超える高速で、音の折り返しノイズ（エイリアシング）が出る。第一版は許容して文書に書く。
- ミキサーに JS のリサンプラーを持ち込む。リマップしていない音は同じ道に残し、バイト単位の一致で守る。

## 8. 決めたこと

オーナーが、私の推しのとおりに承認した（4 点）。あわせて「全体のルールに照らして、共通のパラメータルールになるように」と指示があり、4.2 でその突き合わせをした。

1. **負の `speed` の開始位置は `|speed| × duration`。** `speed: -1` は元の最初の `duration` 秒を逆向きに再生する。末尾から逆再生したいときは `initial: { time: <元の長さ> }` と書く（秒数。負の `time` は終わりからなので、`-0` は書き分けられない点に注意）。
2. **子の `at` が時計の届く範囲の外にあるときは、警告にする。**
3. **見せ場の作品は 1 本付ける。** 企画: 「巻き戻し」（タイトルの出現を 4 倍速で巻き戻し、テープ式の音程の下がる音を付け、一度静止してから、スローで再生し直す）。細部は計画の段階で、先に設計してから作る。
4. **映像のキャッシュ鍵の変更は、独立した手順にする。** 既存の作品がピクセル一致することを確かめてから先へ進む。

共通ルールの指示を受けて私が決めたこと（オーナーが読んで直せる）:

- 層のキーは **`speed`**（最上位の固定設定）と **`time`**（`initial` とキーフレーム）。`particles` の `speed`（px/秒）との取り違えは、別名の警告と文書で防ぐ。
- **`time` の負の値は、中身の終わりから**（`at` や `poster` と同じ共通ルール）。試作で検証していない新しい挙動なので、テストで確かめる。
- **`sfx` / `music` に `speed` / `time` は書かせない**（警告して `pitch` を案内）。合成音を時間ワープに通す経路は、第一版では作らない。
- **合成層の `loop` は入れない**（4.2 末尾）。

## 10. 実装での調整（実機で測った値と、計画からの変更）

- **映像の `awaitFrameAt` を Task 4 に前倒し:** snapshot / 書き出しは `Movie._awaitVideoFrames` を通り、「外側の時間」で映像を描き直すため、`speed ≠ 1` だと誤ったフレームになる。`VideoSequence` に `selfTimed` を付け、Movie は範囲のガードなしで呼ぶ（three 層は今までどおり）。映像は自分の `_cur`（タイムラインが最後に書いた値）で描く。
- **フレーム境界の許容を 2 か所で広げた:** 映像の検索に 5e-5 秒、grain のフレーム番号に 1000 分の 1 フレーム。GSAP が時間を約 1e-8 秒に丸めるため、境界の時刻が 1 つ手前になることがあった（grain は 255/255 の差が出ていた）。
- **音:** `inspectAudio` / `limitMix` が、局所時間の音の区間を映像の時間で読む（`playSpan`）。リマップした合成層の中の効果音が、時計に付いてくる（試作では未検証、実機で確認）。時計が止まって音が切れるときは「its composition's clock only reaches X s」と言う（`clockReach`）。
- **タイムライン:** 局所時間の行・トランジションは `local` で印を付け、局所の秒のまま。外側の時間の併記はしていない（巻き戻しなどの非単調な時計は、外側の時間が 1 つに決まらない）。`resolveAtList` は局所の行を名前で引くと、合成層の名前を案内する。
- **`duration` の既定:** 映像・音ファイルは、定速のとき「ファイルの長さ ÷ |speed|」（メモにない判断）。
- **未検証の防御:** 合成層の `inner.time(end); inner.time(0)` の初期化は、これを必要とする失敗を再現できなかった（変異でも、試作の失敗例でも差が出ない）。
- **測定（headless Chrome、M1 Pro）:** 映像 9 ケースと加速は、時計の指す 1 フレーム以内、シーク順序の差は 0、書き出しの読み戻しも 1 フレーム以内。合成層 4 種の時間マップ × 6 機能は、リマップなしの基準と 60/255 以内（縁のアンチエイリアス）、シーク順序の差は 0。音: 440 Hz → speed 2 で 880 Hz、0.5 で 220 Hz、掃引の逆再生は 950 → 250 Hz、静止は無音。200 層の 1 フレーム: 0.47 ms 対 0.46 ms。`cubic-bezier`: CSS との最大差 9.8e-7。
- **既知の限界:** three 層がリマップした合成層の中にあると、時刻が外側のまま。音程は速度についてくる（タイムストレッチなし）。2 倍超は折り返しノイズを除去していない。
