02Start with one sentence

You do not have to learn it. Just ask.

Tell any AI this one sentence. It opens the repository, understands what to do, and gets to work. Change the ending to what you want to see and hear.

Paste this into any AI

Use https://github.com/yjmtmtk/pixi-effects to make a video: a 10-second title for a bakery, warm cream colours, a soft chime at the end

Try another ending, or click the orange text and write your own:

Works withChatGPTClaudeCodexCursorClaude Codeand any AI that can open a link.

  1. The AI opens the repository, and its first screen tells it where to go.

    The README top says it plainly: "do not read the whole repository". An AI that can run commands is sent to AGENTS.md and ai/SKILL.md. One that can only write text, such as a browser chat, is sent to ai/CHAT.md.

  2. It writes the video as plain data in one HTML file, and checks it.

    With a shell it runs the check tool, which writes a contact sheet the AI looks at before it says it is done. Warnings are written as instructions, with a "did you mean". In a chat, the page shows them in a red box instead.

  3. You open the file, watch it, and press download.

    The player bar has a download button for the MP4. An AI with a shell can also render it with one command: npx pixi-effects-render your-video.html -o your-video.mp4.

Honestly

  • The AI has to be able to read a web page, to open that link.
  • In a chat with no preview window, save the file it gives you and open it in a browser.
  • This is a young, experimental library. The first try may need a couple of rounds: paste back what the red box says and the AI fixes exactly that.
03What you get

A small vocabulary for a whole film.

A video is layers, keyframes and expressions, the way After Effects thinks, but written down as data. Six things come in the box.

ease: 'power2.out'timevalue
T1 Write

A video is a tree of plain objects.

Text, shapes, images, video, audio and nested compositions, each with at duration initial keyframes filters mask. Repeated structure is a JavaScript loop that returns objects.

Numbers can be expression strings. Same data, same video: it is seeded and never reads the wall clock.

'GW/2''min(W,H)*0.4'seededdeterministic
T2 Run

The browser is the renderer.

Play, scrub and export MP4, WebM or MOV with no server, using WebCodecs through mediabunny. Playback, scrubbing and export share one frame path, so the preview equals the export.

A starter is one HTML file with an import map, no bundler. From a script: npx pixi-effects-render page.html -o out.mp4 (Node 22 and Chrome).

T3 Look

After Effects' model, with a 2.5D camera.

Layers, keyframes, expressions, masks, blend modes and nested compositions. Depth with threeD z rotationX/Y and a camera layer: dolly zoom, orbit and cameraPath() flights. A real three.js layer is optional.

blurnoisecolorMatrixglowdropShadowcrtrgbSplitoldFilmglitchpixelatetwist+ 30 more by name
crossfadewipeirisslidedipzoomdissolvechroma key
T4 Move

Text, particles, morphing, motion blur.

Helpers that are seeded and baked into keyframes: wiggle stagger animateText (per letter, word or line), followPath, path morphing, draw-on strokes with trimEnd and particles().

True motion blur at export, by averaging sub-frames. Filters are used by name with no import: four from pixi.js and the 38 of pixi-filters.

T5 Sound

No audio files. Music written as text.

sfx: 11 synthesised presets (click, pop, swoosh, riser, hit, chime and more), or your own voices. music: notes, chords and drum patterns as strings, with 8 instruments, 10 drums, swing, fades, tempo changes and loops.

Deterministic, and in the exported file at the same moment it plays. Visuals can listen: audioEnvelope() musicEnvelope() react(). Hear eight tunes written as text in the music lab.

T6 Present

Slides that move, and a player you can drop in.

deck() and a Presenter turn a movie into a talk: stops, arrow keys, click or swipe, a page overview, a presenter view with notes, and PDF export.

The player UI is a drop-in video-style controller (play, scrub, volume, fullscreen, download) with one accent colour, or build your own on the movie's events.

04Built for AI

Written by a model. Checked by one.

Writing the data is the easy half. The tools in the package are for the second half: looking at what was made and fixing it, without a person watching every render. The way in is one sentence: Start with one sentence.

  1. WriteThe model reads a skill, a cheatsheet and tested recipes.
  2. CheckOne command opens the page in headless Chrome and reports.
  3. LookA contact sheet and a timeline show the film as images.
  4. FixWarnings are phrased as instructions. Exit code 0 or 1.

write → check → look → fix → check again

One command that reads the page like a reviewer.

pixi-effects-check opens the page in headless Chrome and reports what a human would catch by eye.

  • library warnings, written as instructions with a "did you mean"
  • layout problems: text cut off, things off the canvas
  • sound problems, from movie.inspectAudio()
  • a contact sheet PNG and a timeline
  • a real export, decoded again to prove it works
$pixi-effects-check page.html

A timeline you can read, and so can a model.

pixi-effects-view opens the page with a zoomable timeline under it: one row per layer, keyframes as diamonds, transitions as shaded bands. Click a layer name to jump to its start.

It is a viewer, not an editor. There is no GUI editor, and that is on the honest list below.

$pixi-effects-view page.html

For an AI with a shell: a skill. For one without: a link.

An agent with a shell and a browser, such as Claude Code, reads ai/SKILL.md. There is also a cheatsheet, tested recipes, a list of pitfalls, and llms.txt / llms-full.txt. The recipes in the docs are executed by the test suite.

Chat-only entry: nothing to install

In ChatGPT or Claude in a browser with no shell, paste this (or the one sentence above, which sends the AI here). The model returns one HTML file that loads from one CDN and shows warnings in a red box you can paste back. Use the download button in the player bar for the MP4.

06Comparison

Remotion, fframes, and where we fit.

All three write video as code. They make different bets. This is a fair side-by-side, including the places pixi-effects is the wrong choice. It does not claim to be faster or better overall.

Checked 2026-10-07, from their own pages: remotion.dev · fframes.studio · fframes on GitHub. Anything their pages do not say is marked "not stated".

Comparison of pixi-effects, Remotion and fframes
Aspect pixi-effects0.16.1, MIT Remotionremotion.dev fframesfframes.studio
How a video is written Plain data: a tree of text, shape, image, video, audio and nested-composition objects. Repetition is a JS loop. React: "Create videos and motion graphics with React." Rust and SVG.
Where it runs, what you install In the browser. One HTML file with an import map, or npm install. Headless render needs Node 22 and Chrome. Server-side and client-side rendering, batch rendering, and Remotion Lambda for cloud rendering. A Player component plays in your own app. Native, with no headless browser. Prebuilt binaries for macOS and Linux (arm64, x86_64). Building needs Rust and ffmpeg libraries. Windows needs a separate FFmpeg setup.
Preview and editing No GUI editor. Play and scrub in the page; a zoomable timeline viewer. Preview equals export. Remotion Studio, interactive with drag-and-drop. Also Editor Starter and Recorder. A real-time GPU preview window, and a browser-based editor (WebAssembly) with a timeline.
Rendering approach WebGL in a browser (PixiJS v8), encoded with WebCodecs; MP4, WebM, MOV. Not a native GPU renderer. Needs a WebCodecs browser. As above: server, client, batch and Lambda. GPU (Skia on Metal or Vulkan), ffmpeg libraries linked in for encoding. Its README says "about 10x faster" than its own CPU backend.
Speed figures No benchmark against others. On the author's laptop a typical 12 s gallery piece exports in about 10 s; a 48 s 1080p film with 16-sample motion blur took 99 s. Not stated. Its page: built by Codex, "36 minutes to build, 24 seconds to render". Its README mentions a 128-second video rendered in 36 seconds.
Sound Synthesised sfx (11 presets) and music written as text, no audio files. Audio-reactive visuals. Not compared here. An audio analyze command: loudness (LUFS), true peak, clipping.
AI-agent workflow check (warnings, layout, sound, contact sheet, timeline, real export decoded), view, a skill, llms.txt, and a chat-only entry. 11 agent skills via npx skills add remotion-dev/skills; agents preview in Remotion Studio. No MCP is mentioned on its page. A skill for coding agents (npx skills add), and inspect for missing fonts and text cutoff.
Licence MIT. No company licence. Source-available, not MIT. Free for individuals, non-profits and organisations of up to 3 people. Larger for-profit organisations need a Company licence, from $100 / month (usage-based); Enterprise from $500 / month. MIT.
Maturity Experimental, pre-1.0. The API can change between minor versions. Smaller ecosystem. Verified in Chrome by the author; Safari and Firefox are documented, not independently verified. About 62,000 GitHub stars, as its page states. Large ecosystem of React components. Its README does not say whether the API is stable, and says the project "stayed unreleased for years" before this release.
Best for Data-driven or AI-written motion graphics that must play on the web and export to a file, with no server. React teams that want a visual studio and cloud rendering at scale. Rust developers who want native GPU rendering where speed is the point.

Choose Remotion when

  • Your team already writes React and wants videos built from components.
  • You want to scrub and tweak in a visual studio (Remotion Studio, drag-and-drop).
  • You need cloud rendering at scale (Remotion Lambda), or a Player inside your product.
  • You want a large ecosystem, about 62,000 GitHub stars on its page.

Check first

  • The licence is source-available: free up to 3 people, a paid Company licence above that for for-profit organisations.

Choose fframes when

  • Render speed is the point, and Rust and SVG are home for you.
  • You want native GPU rendering (Skia on Metal or Vulkan) with no headless browser.
  • You are on macOS or Linux and happy with prebuilt binaries, or with building from Rust.
  • You want MIT licensing and a real-time preview window or a browser editor with a timeline.

Check first

  • Its README does not say whether the API is stable. Windows needs a separate FFmpeg setup.

Choose pixi-effects when

  • The same data should play on the web and export to MP4, with no server.
  • An AI model writes the video and you want tools that check it: warnings, a contact sheet, a timeline.
  • You want sound with no audio files, and music written as text.
  • You want MIT and a single HTML file as a starter.

Do not choose it when

  • You need a GUI editor. There is a timeline viewer, not an editor.
  • You want a mature React ecosystem, or an API that is settled and past 1.0.
  • You need cloud rendering at scale.
  • You need the fastest native GPU renders. This draws with WebGL in a browser.
  • You want to edit existing footage. A video layer plays a clip inside a composition, nothing more.
  • Your export browser has no WebCodecs.

A note on trust. Facts about Remotion and fframes are what their own pages say on 2026-10-07 and may have changed. Their logos are not used. Speed figures in the table come from different machines and different pieces, so they are not comparable with each other.

07Get started

One minute, three ways in.

Or just ask an AI with one sentence. Otherwise pick the way that matches how you work. Each ends with a video you can play, and the player bar has a download button.

01

With a bundler or Node

Install it, copy the snippet from the top of this page, and run movie.play() or movie.render({ format: 'mp4' }). PixiJS and GSAP are peer dependencies; three and pixi-filters are optional.

$npm install pixi-effects pixi.js gsap
02

One HTML file, no build step

An import map loads the library from a CDN. The repo's ai/template.html is the full starter, with the player and a loader. Load the dist/ files as they are, not a re-bundled build.

Write the video. Play it. Export it.

What it is

pixi-effects is declarative composition and video rendering for the web, built on PixiJS v8. An AI writes a video as data; the same data renders to a file and plays on the web.
