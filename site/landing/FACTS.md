# Fact sheet for the pixi-effects landing page (checked 2026-10-07)

Use ONLY these facts. Do not invent numbers, benchmarks, users, quotes, awards, or features. If a claim is not here, leave it out.

## pixi-effects (this project)
- **The timeline is the library's own** (measured 2026-10-10 on the author's Mac, Chrome): a value at a time is computed from the data and the time alone, so scrubbing in any direction, looping and export agree. Against the GSAP build on 92 pages by frame hash: 77 identical, 9 within 3/255, the rest explained (a formula GSAP changed between 3.12 and 3.15, one page that is not reproducible). The timeline step of a frame took 1.3 to 11 times less time (0.28 ms to 0.058 ms on a 530-layer piece); a whole frame (3 to 4 ms) is dominated by drawing and changed by 1 to 15 %. A page loads about 25 KB (gzip) less. Do not say "faster video"; say what was measured.
- Name: **pixi-effects**. Tagline source (repo): "Declarative composition and video rendering for the web. Built on PixiJS v8." North star: "An AI writes a video as data; the same data renders to a file and plays on the web."
- Version 0.46.0, **experimental / pre-1.0** (the API can still change between minor versions). MIT licence, no company licence. npm package `pixi-effects`. Repo: https://github.com/yjmtmtk/pixi-effects. The author's X account is https://x.com/t_yjm (the footer links it as "Author on X"; do not put it in the hero, and do not promise updates or announcements there).
- Built on PixiJS v8 (WebGPU first, WebGL as the fallback), mediabunny (WebCodecs encoding), and a timeline of its own (since 0.27.0; it replaced GSAP). The ease names and the way `to` / `from` / `set` read are GSAP's, with thanks. Runtime dependency: only `mediabunny` (PixiJS is a peer dependency; three.js and pixi-filters optional).
- **A video is plain data**: a tree of plain objects (text, shapes, images, video, audio, nested compositions) with `at` / `duration` / `initial` / `keyframes` / `filters` / `mask`. Repeated structure is a JS loop that returns objects. Numbers can be expression strings like `'GW/2'`, `'min(W,H)*0.4'`. Same data => same video (deterministic, seeded; no wall clock). Playback, scrubbing and export all use the same frame path: the preview equals the export.
- **Runs entirely in the browser**: play, scrub and export MP4 / WebM / MOV with no server (WebCodecs via mediabunny). A starter is ONE HTML file with an import map (no bundler needed); npm install also works. Headless render from a script: `npx pixi-effects render page.html -o out.mp4` (needs Node 22 and Chrome).
- Browser support as documented in the README: Chrome 94+, Edge 94+, Safari 16.4+, Firefox 130+ (playback and MP4/WebM/MOV). The author has verified it in Chrome; Safari and Firefox are documented but not independently verified.
- Light, shadows, fog (0.24): `light` layers (`ambient` `point` `spot` `parallel`) shade `threeD` layers per pixel, `castsShadows` throws soft shadows (a receiver takes up to 4 casters), a camera can add fog. Depth of field (0.21): a rack focus on the camera.
- Shaders, warps, mattes, blends (0.22, 0.23, 0.25): a `shader` layer draws a Shadertoy-style `mainImage` (GLSL ES 3.00) with animated uniforms; the `warp` filter (`wave`, `haze`); named mattes (`mask: 'name'`, alpha or luma, a list is an intersection); 18 CSS blend modes.
- A `three` layer can live in the composition's space (0.40): `followCamera` / `followLights` / `followFog` make the composition's camera, lights (with shadows) and fog drive a three.js scene, so one `cameraPath()` or `orbit()` flies through the flat layers and a glTF model together; `threeGltf` loads a model and poses its clip by the time, `pixi-effects probe model.glb` lists its clips and size, and `check` holds a three layer to "a function of the time".
- Interaction (0.42): `movie.hover({ onEnter, onLeave })` (which layer the pointer is over, following a picture that moves under it), `pick(x, y, { alpha })` (the picture, not the box), `hit.three.grab(plane)` (drag an object of a three layer on a floor or a wall), `movie.redraw()`; recipes `pick-click`, `drag-drop`, `drag-3d`.
- `movie.pick(x, y)` (0.41): what is under a point of the canvas at the frame on screen, for flat layers (by their own shape), `threeD` cards (by their projected quad) and `three` layers (by a ray, naming the object), with `pickAll`, `canvasPoint(event)` and `check --at T --pick X,Y`: what an interactive page needs to know what was clicked.
- Look and feel, After Effects model: layers, keyframes, expressions, masks, blend modes, nested compositions, a 2.5D camera (`threeD`, `z`, `rotationX/Y`, a `camera` layer, dolly zoom, orbit, `cameraPath()` flights), optional real three.js layer.
- Motion helpers (all seeded, baked into keyframes): `wiggle`, `stagger`, `animateText` (per letter / word / line), `followPath`, path morphing, draw-on strokes (`trimEnd`), `particles()`, `deck()` and a `Presenter` (slides that move: stops, arrow keys / click / swipe, page overview, presenter view with notes, PDF export), true motion blur at export (sub-frame averaging).
- Filters by name with no import: `blur noise alpha colorMatrix` (pixi.js) and the 38 filters of `pixi-filters` (`glow dropShadow crt rgbSplit oldFilm glitch pixelate twist …`); eight scene transitions (`crossfade wipe iris slide dip zoom dissolve luma`); chroma key.
- **Sound with no audio files**: `sfx` (11 synthesised presets: click, pop, swoosh, riser, hit, chime…, or your own voices) and **`music` written as text** (notes, chords and drum patterns as strings; 8 instruments, 10 drums, swing, fades, tempo changes, loop). Deterministic and in the exported file at the same moment. Audio-reactive visuals: `audioEnvelope()`, `musicEnvelope()`, `react()`.
- **Built to be written by AI, and checked by AI**: `pixi-effects check page.html` opens the page in headless Chrome and reports library warnings (written as instructions with "did you mean"), layout problems (text cut off / off-canvas), sound problems (`movie.inspectAudio()`), a contact sheet PNG, a timeline, and a real export decoded again; exit code 0 / 1. `movie.inspect(frame)`, `contactSheet()`, `snapshot()`. `pixi-effects view` opens the page with a zoomable timeline under it. An AI skill (`skills/pixi-effects/SKILL.md`), cheatsheet, tested recipes, pitfalls, `llms.txt` / `llms-full.txt`. A short chat-only entry (`ai/CHAT.md` + `ai/chat-template.html`) for ChatGPT / Claude in a browser with no shell: one HTML file that loads from one CDN and shows warnings in a red box to paste back. The recipes in the docs are executed by the test suite.
- **Interactive movies (0.31)**: `movie.init({ vars })`; a number variable is a plain name in a numeric expression (`'W/2 + shift'`), any variable is `{name}` inside a string (text, colour, asset, sfx, music `notes`); `movie.setVars()`, `movie.resize()`, `movie.rebuild({ composition, vars, width, height })` build the film again beside the old one and swap it in at the same frame (a playing movie keeps playing; calls that overlap are joined; a failure keeps the old film); the mixed sound is reused when it did not change (`audio: 'reused'`). Measured on the author's Mac (Chrome, four gallery pieces with sound): a rebuild takes 11–42 ms with the sound reused; mixing the sound again takes 0.6–0.8 s (spike). `movie.loop` and a loop button + L key on the player. `pixi-effects check / render` take `--var name=value` and `--size WxH` (check: several sizes, a contact sheet each). Nine live samples in examples/interactive/ (rock paper scissors, a scrolling 2.5D city, a tune from four chords, a card for anyone with a batch of MP4s made in the browser, choose your ending, variants, sliders, the pointer, a liquid layout). Limits: a variable moves values, not `at` / `duration`; a rebuild rebuilds the whole composition (not one property); sound starts after the page has been clicked (browser rule).
- Player UI: a drop-in video-style controller (play, scrub, volume, fullscreen, download button); theme with one accent colour; or build your own player on the movie's events.
- Gallery: 43 complete pieces, each ONE HTML file of data, many written by AI models (fable 9, opus 32, sonnet 2, haiku 0), from kinetic type to data stories, 2.5D, a 48 s showpiece "間 MA". Live gallery: https://yjmtmtk.github.io/pixi-effects/examples/gallery/ (posters are in ./assets/posters/<id>.jpg; the pieces are playable on that page). A playground. The page for AI: https://yjmtmtk.github.io/pixi-effects/for-ai.html . Piece ids and titles are in PIECES.txt next to this file.
- Images you may use: ./assets/contact-sheet.jpg (a contact sheet written by the check tool), ./assets/timeline-view.jpg and ./assets/timeline-collapsed.jpg (the timeline viewer), ./assets/posters/*.jpg (gallery posters, 1280x720 or the piece's own ratio).
- **Export speed (measured on the author's M1 Pro, 16 GB, Chrome, 2026-10-08; in-page `movie.render({ format: 'mp4' })` without browser start-up):** most gallery pieces export at 105–115 frames per second, 3.5 to 3.8 times real time at 30 fps: `ma` (1920×1080, 48 s, 1440 frames) 13.7 s; kinetic-manifesto, synthwave-drive (1280×720, 12 s) about 3.2 s. A piece with thousands of particle layers is slower: a firework piece 17.3 s for 12 s (21 fps, 0.7× real time). With the command line (`pixi-effects render`) add about 7 s of one-off start (launching headless Chrome, loading the page). With 16-sample motion blur the 48 s 1080p film took 99 s. These are the author's own numbers on one laptop, not a benchmark against other tools.
- Honest limits (say them plainly, a trusted LP does): pre-1.0 and experimental; **no GUI editor** (there is a timeline viewer, not an editor); smaller ecosystem than the established tools; export needs a WebCodecs browser; it draws in a browser (WebGPU where the browser has it, WebGL otherwise: PixiJS tries WebGPU first and falls back by itself) rather than in a native pipeline and it has not been benchmarked against other tools (do not claim it is faster or slower than them; the numbers above are its own). Not a replacement for editing existing footage (a `video` layer plays a clip inside a composition).
- A real minimal composition (use this style for any code shown):
```js
import { Movie } from 'pixi-effects';
const movie = new Movie();
await movie.init({
  canvas, width: 1280, height: 720, duration: 6, frameRate: 30, background: '#0a0a0f',
  composition: { sequences: [
    { type: 'text', text: 'Hello', at: 0.5, style: { fontSize: 120, fontWeight: 'bold', fill: '#fff' },
      initial: { x: 'GW/2', y: 'GH/2', anchorX: 0.5, anchorY: 0.5 },
      keyframes: [{ at: 0, from: { alpha: 0, y: 'GH/2 + 40' }, to: { alpha: 1, y: 'GH/2' }, duration: 0.6, ease: 'power2.out' }] },
    { type: 'audio', sfx: 'chime', at: 1.1 },
  ] },
});
movie.play();            // or: const mp4 = await movie.render({ format: 'mp4' })
```
